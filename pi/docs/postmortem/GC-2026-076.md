## What happened

Promoted 6 subagent types (`Developer`, `Reviewer`, `Fix`,
`MergerAdvisor`, `Planner`, `Explore`) to the `FIRST` tool-priority
section in the system prompt and the LLM-facing tool descriptions.
The goal was to make the LLM reach for these 6 tools first (instead
of doing manual `read`/`edit`/`write`/`bash`) for Sages-managed
work.

## Root cause

Pre-GC-076, the LLM was reaching for raw `read`/`edit`/`write`
directly even when a Developer/Reviewer subagent would have produced
better evidence (commit history, TDD discipline, 5-dim review).
The fix was to make the 6 subagent types more discoverable in the
tool surface.

## Fix

- P1: the orchestrator's LLM-facing tool list (the `FIRST` block in
  the system prompt) was reordered to put the 6 subagent tools at
  the top.
- P2: each of the 6 subagent types' prompt was updated with a
  "FIRST" section that explicitly says "if you're a Sages-managed
  subagent, use the canonical task creation flow" (TaskCreate +
  agentType).

## Follow-ups

- Tool-adoption is now driven by `pi-evaluator` (added in a later
  GC). The hard-coded `FIRST` block in the system prompt is still
  useful as a fallback for sessions without `pi-evaluator`.
- The 6-agent `FIRST` sections are still in the subagent prompts as
  a defense-in-depth.
