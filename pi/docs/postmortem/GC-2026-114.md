## What happened

The follow-up to GC-2026-113. With the unified task-feeder
authoritative for spawn + completion + cascade, the legacy dual
paths in `workflow-handler.ts` (its own `spawnAgent` callback +
`agentToTask` map) and `decompose-cascade.ts` (its own
`decomposeAgentMap` + cascade listener) were dead code that did
the same work the feeder already does. This GC removes them.

Also: `cfg.autoCascade` was a no-op config gate (cascade is
unconditional via the feeder) but the key + the settings-menu
toggle + the listener that checked the key were still in the
codebase. This GC removes the key, the menu item, and the gate.

After this GC: `subscribeWorkflow` and the extension factory
share a single `agentTaskMap` (the one the feeder populates).
Workflow tasks, decompose tasks, user tasks, and TaskExecute all
flow through one feeder with one map.

## What changed

- **`workflow-handler.ts`**: `subscribeWorkflow` signature changes
  from `events + spawnAgent + onTaskChange?` to
  `events + feed: { maybeAutoSpawn } + agentTaskMap + onTaskChange?`.
  The local `agentToTask` map is removed. The 4 spawn sites
  (initial Implement + Fix + Redesign + cascade) all delegate to
  `feed.maybeAutoSpawn(task)`. The cascade-on-completion loop
  is removed (the feeder's listener handles cascade for all
  task types). The 2 `subagents:completed` / `subagents:failed`
  listeners look up the task via the shared `agentTaskMap` (no
  local cache).
- **`decompose-cascade.ts`**: deleted. The `isDecomposeTask`
  predicate, the `cascadeSpawn` filter, the `decomposeAgentMap`,
  and the three listeners (`decompose:spawn` register +
  `subagents:completed` cascade + `subagents:failed` revert) are
  all gone. The unified feeder's `subagents:completed` listener
  walks the store for newly-unblocked feedable tasks and
  auto-spawns them, which covers decompose-chain cascade
  naturally. The `decompose:spawn` event channel is no longer
  emitted.
- **`tasks-config.ts`**: `autoCascade?: boolean` removed from
  the `TasksConfig` interface.
- **`ui/settings-menu.ts`**: the "Auto-cascade agent tasks" menu
  item + its `onChange` branch are removed.
- **`pi-tasks/src/index.ts`**: the
  `registerDecomposeCascade({...})` call is removed. The comment
  block that explained the three legacy cascade listeners is
  updated to reflect that the feeder handles all three.
- **`pi-tasks/src/orchestrator-task.ts`**: the comment that
  pointed at `decompose-cascade.ts`'s `isDecomposeTask` filter
  is updated to point at the unified feeder's generic cascade.
- **Test fixtures**:
  - `pi-tasks/test/workflow-handler.test.ts`: `setup()` now
    builds a `feed: { maybeAutoSpawn }` + `agentTaskMap` and
    passes them to `subscribeWorkflow`, replacing the old
    `spawnAgent` vi.fn. The 3 test bodies that read
    `spawnAgent.mock.calls[N][0]` are updated to read
    `spy.calls[N].task`. The "workflow task active marker"
    test is renamed to reflect that the active-marker
    side-effect lives in the extension factory's `onTaskChange`,
    not in `subscribeWorkflow`'s `spawnAgent`.
  - `pi-tasks/test/path-b-e2e.test.ts`:
    `setupWithRealIds()` is updated similarly.
  - `pi-tasks/test/decompose-cascade-e2e.test.ts`: deleted.
    The cascade behavior is now covered by
    `pi-tasks/test/task-feeder.test.ts` (from GC-2026-108),
    which tests the unified feeder's `cascadeSpawn` directly.

## What broke / what we had to fix mid-implementation

- **`pi-tasks/test/workflow-handler.test.ts` "active marker"
  test** referenced the removed `spawnAgent` callback by name in
  its test name. Renamed the test to reflect the new model
  (the active-marker side-effect lives in the extension
  factory's `onTaskChange`, not in `subscribeWorkflow`).
- **`pi-tasks/test/workflow-handler.test.ts` "last-review
  evidence file" tests** had `agentTaskMap` referenced
  without being declared (the local `feed` mock sets it but
  the variable was scoped to the closure). Added an explicit
  `const agentTaskMap = new Map()` declaration in those tests.
- **5+ test files** had `c[0].subject` / `c[0].metadata.X` to
  read the old `vi.fn` mock's call array. Updated all of them
  to read `c.task.subject` / `c.task.metadata.X` from the new
  `spy.calls[N].task` shape.
