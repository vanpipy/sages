# GC-2026-063 — summary-by-default output for orchestrator tools

> **Date:** 2026-08-21
> **Status:** Resolved
> **Severity:** major

## What happened

The four orchestrator tools `goal_contract_create`, `dag_synthesize`,
`task_dispatch`, and `orchestrator_audit` each `JSON.stringify`'d their
**full payload** into `content[0].text` — every SC and scope entry of the
goal contract, every task of the DAG (including each task's full `prompt`),
every task of the dispatch plan (full prompts again), the audit's
`phase_guidance` (long per-phase prose), `tasks_to_audit` (full report
paths), `inline_findings`, `failure_mode_stats`, and `phases`.

None of this was new information for the LLM — it had just supplied the
input one tool call earlier, and the canonical state lived on disk at
`.pi/orchestrator/goal-GC-*.yaml`, `dag-DAG-*.yaml`, and
`audit-state-DAG-*.yaml`. The full echo was pure redundancy.

Concrete cost observed in a single GC-2026-062 workflow: `dag_synthesize`
returned ~2 KB of redundant JSON per task (3 tasks × ~700 bytes of
prompt), `task_dispatch` repeated the same prompts (another ~2 KB),
`orchestrator_audit` init returned ~3 KB of `phase_guidance` that the LLM
never needed. The round-trip was 6–8 KB of context per workflow for
zero new signal.

## Root cause

The tools were modeled as "return the canonical state object" — a
natural but context-inefficient pattern when the LLM itself is the
producer of that state. The fix has to invert the default: return the
smallest payload that still lets the LLM do its next step, and let
callers opt into the full payload when they need it (e.g. when reading
the full DAG to follow up).

## Fix

Add an optional `verbose` parameter to each of the four tools. Default
(omitted / `false`) returns a compact `summary` (or the smallest payload
the LLM needs to make the next decision). `verbose: true` returns the
full payload unchanged.

| Tool | Default summary | `verbose:true` adds |
|---|---|---|
| `goal_contract_create` | `{id, title, success_criteria, anti_goals, scope_include, scope_exclude}` | `goal_contract` |
| `dag_synthesize` | `{id, goal_id, batch_count, tasks:[{id, description, batch, subagent_type, depends_on, covers}]}` | `plan` |
| `task_dispatch` | dispatch table with `{task_id, subagent_type, isolation, run_in_background, prompt_preview}` (120-char first 120 + "...") | full `prompt` |
| `orchestrator_audit` init | `{audit_identity, workflow_summary, validation(findings_required_min), phase, intent, status}` | `phase_guidance`, `tasks_to_audit`, `inline_findings`, `failure_mode_stats`, `phases` |

Exported helpers (`summaryForGoal`, `summaryForPlan`, `summarizeDispatch`)
carry the unit-testable summary shape. The complete/findings/transition
subpaths of the audit and dispatch tools are unaffected (they were
already summary-shaped).

## Follow-ups

- `pi/catalogs/gate.json` regenerated as part of the change (the three
  files are catalog `_source_files`). Regenerate + revert timestamp-only
  touches in sibling catalogs, the canonical way.
- Consider propagating the same `verbose` pattern to other tooling
  (e.g. `sages_reminder`, `sages_todo`) that returns full state payloads
  the LLM may not need.
- Consider a `README` line that calls out the `verbose` flag so users
  discover it.
