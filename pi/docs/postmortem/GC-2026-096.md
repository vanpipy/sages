# GC-2026-096 — AFT install integration

## What happened

Sages treated AFT as a manual post-install step. `pi-orchestrator/templates/aft.jsonc` shipped in the repo but `install.sh` never copied it; `@cortexkit/aft-pi` was never installed; the AFT binary was never downloaded. Every fresh install hit the user's first session with AFT in "degraded" mode — `aft_search` / `aft_callgraph` / `aft_refactor` not registered — unless they manually ran `npx @cortexkit/aft setup --harness pi --yes`. The same pattern that `codebase-memory-mcp` (binary download + checksum) and `pi-mcp-adapter` (npm peer install + settings.json register) already solved.

This GC bakes the full install path into `install.sh`: three soft-fail install steps (config + npm peer + binary), their mirror uninstall steps, and wiring into `install()` and `uninstall()`. Design at `.pi/orchestrator/designs/2026-10-01-aft-install-integration.md`.

## Root cause

`install.sh` (lines 30-36, pre-GC) documented AFT as a "Manual-only carve-out (intentionally NOT auto-installed)" with a comment that pinned the rationale to "memory #25". The intent was to keep binary provisioning with the AFT team (`cortexkit/aft`) rather than have Sages own it. In practice this left the AFT template + plugin + binary entirely outside the Sages install path, and the user hit a degraded first-session UX on every fresh checkout.

The fix flips the ownership: Sages owns the install path end-to-end (mirroring the codebase-memory-mcp + pi-mcp-adapter precedents), and the binary version is pinned to whatever the just-installed npm peer bundles (`$AFT_NPM_DIR/package.json#version`). The "memory #25" rationale survives in spirit — AFT CLI still owns the binary download format and the onnx model provisioning — but the install trigger now lives in install.sh.

Per the soft-mode takeover contract, the orchestrator completed the Implement → Review → Merge pipeline manually on the worktree's branch. Filed separately as a candidate follow-up GC against `workflow_run`.
- **Test author's RED-phase bugs**: the Developer agent's test had three bugs the orchestrator fixed in the GREEN phase: (1) `$scriptPath` (shell var) where `${scriptPath}` (JS template interpolation) was needed; (2) the install_aft_binary soft-fail test assumed `HTTPS_PROXY=127.0.0.1:1` would fail fast — in dev environments with a working system proxy, curl falls back to direct connection and the 92MB download takes >5s. Fix: bump `it()` timeout to 15s. (3) shellcheck regression test counted URL mentions of `SC\d{4}` as warnings, inflating the count by 1 — fix was to remove the pre-existing 2 unused constants. Lesson: TDD's RED phase should be verified to fail for the RIGHT reason before counting it as a real RED.
- **Postmortem + gc-index bootstrap**: `pi/docs/postmortem/` and `pi/docs/gc-index.md` were absent on disk (post-2026-08-24 reset per AGENTS.md). This GC is the first to write institutional memory in this cycle; the gc-index entry is bootstrapped here with a minimal header so `bun run verify:catalog` doesn't trip the "orphan postmortem" gate.
