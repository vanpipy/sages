# GC-2026-089 — Postmortem (post-hoc reconstruction)

## What happened

`pi-coding-agent`'s `render-utils.js#getTextOutput` reads
`result.content.filter((c) => c.type === "text")`. Without an explicit
`{content: [{type: "text", text: <string>}]}` envelope, the renderer
crashed with `TypeError: Cannot read properties of undefined (reading
'filter')`. The 8 Sages orchestrator tools (`goal_contract_create`,
`workflow_run`, `subagent_status`, `subagent_steer`, `subagent_abort`,
`subagent_resume`, plus 2 DAG-state wrappers in `task-dispatcher.ts`)
were returning plain JSON without the envelope.

## Root cause

Each orchestrator tool's `execute` was returning plain JS objects
(`{ok: true, contract: ..., path: ...}` etc.) directly. The
canonical ToolResult shape was assumed in some helpers but not
enforced. GC-2026-085 had previously fixed the same bug class in 2
different tools (`todowrite_*`); the same pattern kept recurring
each time a new tool was added.

## Fix

Commit `1e57f0f merge(GC-2026-089): defensive ToolResult wrapper for 8
orchestrator tools` added an inline try/catch + `Content[%]`
wrapper to all 8 tools. The wrapper caught future regressions by
construction — every tool must return either a `ToolResult` or be
wrapped before crossing the renderer boundary. GC-2026-090 then
extracted the wrapper into a single `wrapRegisteredTool` helper
(see that GC's postmortem).

## Verification

TypeError no longer triggered; renderer passed all 8 tool outputs
through `getTextOutput` successfully. The post-GC-090 helper
consolidates this fix into a single test surface
(`registered-tool-wrapper.test.ts`).
