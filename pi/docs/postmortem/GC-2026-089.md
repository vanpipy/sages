# GC-2026-089 — Defensive ToolResult wrapper for 8 orchestrator tools

## What happened

In a single Sages session, pi-coding-agent's interactive TUI crashed **twice** with the same stack trace:

```
TypeError: Cannot read properties of undefined (reading 'filter')
    at getTextOutput (.../dist/core/tools/render-utils.js:38:39)
    at ToolExecutionComponent.createResultFallback (.../dist/modes/interactive/components/tool-execution.js:110:29)
    ...
```

The crash was identical to **GC-2026-085** (commit `e586f30`): a registered orchestrator tool returned a plain JS object (no `.content` field), and pi's renderer called `.filter()` on undefined.

GC-2026-085 fixed two tools (`todowrite_compile`, `todowrite_progress`) but the same bug existed in **eight more orchestrator tools** that GC-2026-085 missed:

| File | Line | Tool | Pre-fix return shape |
|---|---|---|---|
| `pi-orchestrator/src/task-dispatcher.ts` | 362-364 | `task_dispatch` | raw `executeTaskDispatch` result |
| `pi-orchestrator/src/dag-synthesizer.ts` | 619-621 | `dag_synthesize` | raw `executeDAGSynthesize` result |
| `pi-orchestrator/src/goal-contract.ts` | 364-366 | `goal_contract_create` | raw `executeGoalContractCreate` result |
| `pi-orchestrator/src/orchestrator-audit.ts` | 216-218 | `orchestrator_audit` | raw `executeOrchestratorAudit` result |
| `pi-orchestrator/src/subagent-control.ts` | 375 | `subagent_status` | raw `executeSubagentStatus` result |
| `pi-orchestrator/src/subagent-control.ts` | 385 | `subagent_steer` | raw `executeSubagentSteer` result |
| `pi-orchestrator/src/subagent-control.ts` | 395 | `subagent_abort` | raw `executeSubagentAbort` result |
| `pi-orchestrator/src/subagent-control.ts` | 405 | `subagent_resume` | raw `executeSubagentResume` result |

The session hit the crash first when calling `task_dispatch` (returned empty `[]`, no useful content); then again when calling `subagent_status`. Both calls would have crashed any LLM-agent that invoked the tool.

## Root cause

Two layers of drift:

1. **Original drift (pre-GC-2026-085)**: `pi-coding-agent`'s `registerTool` returns a `ToolResult` envelope (`{content: [{type, text}]}`), but Sages' orchestrator tools' `execute:` arrows returned plain objects. GC-2026-085 caught two cases but missed eight more.
2. **Latency drift**: GC-2026-085's fix was the only test surface (`todowrite-tool-result.test.ts`) — the unit tests for the other eight tools bypassed the `registerTool` boundary, so the integration gap was invisible. The pattern repeated.

Additionally, GC-2026-085's chosen pattern (`return {content: [{type: "text", text: JSON.stringify(result)}]}`) was repeated by hand in each tool — a copy-paste pattern that guaranteed some sites would be missed. The integration tests for `executeDAGSynthesize`, `executeOrchestratorAudit`, `executeGoalContractCreate` all bypassed the registered-tool boundary.

## Fix

Apply the canonical `ToolResult` wrapper at every `registerTool` boundary in `pi-orchestrator/`, mirroring GC-2026-085. The wrapper:

1. Awaits the underlying execute (so async functions resolve before JSON.stringify — `subagent_resume` was async).
2. Detects if the result is **already** in ToolResult shape (`Array.isArray(result.content)`) and passes through unchanged. This handles the legacy tools (`executeDAGSynthesize`, `executeOrchestratorAudit`, `executeGoalContractCreate`) that already returned ToolResult shape pre-wrap.
3. Otherwise wraps in `{content: [{type: "text", text: JSON.stringify(result, null, 2)}], details: result}`.
5. Has a `try/catch` that produces a structured error block on any exception (兜底异常).

New test file `pi-orchestrator/test/tools/orchestrator/registered-tool-shape.test.ts` (17 tests, ~25 KB) pins the shape across all eight tools — including an integration pin that invokes every registered tool and asserts canonical shape in one sweep.

Tools left untouched: `sages_reminder` (already returns canonical shape — `sages-reminder.ts:226-241, 258-273, 276-283`) and `todowrite_*` (fixed in GC-2026-085).

## Follow-ups

1. **GC-2026-088 (paused)**: verifier path offset bug — `verify-catalog.ts:259-260` and `verify-gcdb.ts:31-33` resolve `PI_ROOT` to `pi-orchestrator/` package root, but institutional docs live one level up at `pi/`. Both verifiers silently pass without inspecting real coverage. Resume as separate GC after this lands.
2. **Long-term refactor**: introduce a shared `wrapRegisteredTool(name, execute)` helper that all tools route through. The copy-paste wrapper is a maintenance trap — this GC-2026-089 was the second round. A single helper would prevent the pattern from drifting again.
3. **Subagent resume was async**: easy to miss — `subagent-control.ts:294` declares `async function executeSubagentResume`. The wrapper had to await to serialize the resolved value. Track all async `execute*` functions in a single lint rule.
4. **Catalogs**: `gen-catalog` regenerated. The hash drift in `gate.json` reflects that the registered-tool execute arrow source line numbers changed.
