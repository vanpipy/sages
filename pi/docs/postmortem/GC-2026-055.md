# GC-2026-055 — Auto-install routines + per-type fixdirectives + 2 WARN fixes

> **Date:** 2026-08-20
> **Status:** Resolved
> **Severity:** major

## What happened

Three improvements that close the original 4-phase design and clean
pre-existing debt:

1. **Routine auto-install on session_start** — the 3 routine
   templates (`sages-session-wrap` / `sages-resume` /
   `sages-watchdog`) shipped in GC-2026-053, but they required
   manual `/routine-install <name>`. Most users never noticed them;
   the watchdog and cross-session resume were effectively dead
   features.

2. **Per-type fixdirectives for `sages_reminder`** — mirror
   GC-2026-044 (L2's per-rule fix directives). The 6 reminder
   types previously had default templates (prose), but no
   per-type actionable shell commands.

3. **Clean 2 pre-existing WARN in `verify:soft-mode-mental-model`**
   — `AGENTS.md` and `templates/SUBAGENTS.md` still mention
   "task-count threshold" but `soft-mode.ts` no longer exports
   that exact string. The docs referenced a concept that soft-mode
   no longer uses.

## Root cause

1. **Routines were inert until manual install.** pi-routines'
   design puts installation behind a user slash command
   (`/routine-install <name>`). The 3 Sages templates existed as
   `pi/templates/routines/*.json` but nothing in the extension
   automatically installed them. The watchdog, in particular,
   was useful but invisible — it only worked if the user happened
   to read AGENTS.md and discover the manual step.

2. **Reminder templates were prose, not action.** The original
   `DEFAULT_REMINDER_TEMPLATES` were descriptive text ("DAG has
   not progressed..."). The LLM got the description but not the
   shell command to actually run. This was an L2-pattern gap: L2
   had `RULE_FIX_DIRECTIVES` (per-rule actionable shell), but the
   L1 reminder tool never got the same treatment.

3. **Docs vs runtime drift.** Soft mode was migrated to
   profile-driven in GC-2026-049; the runtime exports
   `profile.dag_threshold` instead of a hardcoded
   "task-count threshold" string. AGENTS.md and SUBAGENTS.md
   weren't updated at the time, so the verifier caught the drift.

## Fix

Two commits in the same branch (`sages/GC-2026-055/auto-install`):

### 1. Auto-install routines

New module `pi/src/tools/routines/sages-routines-install.ts`:

- Reads the 3 templates from `pi/templates/routines/`
- Parses `interval` strings (`'5m'` → `intervalMs: 300000` +
  `intervalHuman: '5m'`) in-house — pi-routines' parser is
  internal and not exported
- Transforms each template into the persisted Routine schema
  (cross-checked against `pi-subagents/.../types.ts` for shape
  compatibility)
- Merges into `~/.pi/agent/extensions/routines/state.json`
- Idempotent: existing routines (matched by name) are skipped, so
  user edits via `/routine-edit` are preserved

`pi/src/extension.ts` `session_start` handler now calls
`installSagesRoutines()` inside a try/catch. Failure doesn't
break session_start; the rest of the extension wiring (L1
advisory reset, soft-mode reminder flag, etc.) is unchanged.

26 new tests cover `parseInterval`, `transformTemplate`, and
end-to-end `installSagesRoutines` (empty dir, missing dir,
malformed JSON, idempotency, mixed batches, real environment
smoke test).

### 2. Per-type fixdirectives

`pi/src/tools/orchestrator/sages-reminder.ts`:

- `SAGES_REMINDER_FIXDIRECTIVES: Record<SagesReminderType, string>`
  maps each of the 6 types to a single-line actionable shell
  command (e.g. STALE_DAG instructs
  `'ls -lt .pi/orchestrator/audit-state-*.yaml | head -1'`).
- `formatReminderText` prefers the fixdirective over the default
  template when no `message` override is provided.
- Fallback: default template still used if fixdirective is somehow
  undefined (defense in depth).

Token discipline preserved: each directive is ≤ 100 chars,
well under the 200-token per-advisory cap that L2 enforces.

### 3. Doc cleanup

Two-line edits in `AGENTS.md`:
- Section heading `## Soft mode and task-count threshold` →
  `## Soft mode and dag_threshold`
- Cross-reference in the red-lines section

One edit in `pi/templates/SUBAGENTS.md`:
- Subagent dispatch note: `task-count threshold` →
  `profile's dag_threshold`

`verify:soft-mode-mental-model` now reports 0 WARN (was 2).
