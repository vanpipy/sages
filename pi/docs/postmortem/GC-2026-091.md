## What happened

The pi-subagents registry mixed case conventions: `Explore`/`Plan` were PascalCase while `developer`/`auditor`/`merger`/`git-expert` were lowercase. The LLM-facing Agent tool description was harder to read and the visual rhythm of the roster was broken.

In parallel, `git-expert` had zero current DAG dispatches. It carried 333 lines of prompt + 170 lines of test for a capability the user decided not to carry forward. Removing it cut ongoing maintenance cost and eliminated the dangling "Defer to git-expert dispatches" advice in `GC-2026-076.md:89`.

Both changes bundle naturally because the canonical-key change touches the same registry layer (`default-agents.ts`, the agent-tool-description roster) as the removal.

## Root cause

Two legacy decisions from the original `@tintinweb/pi-subagents` upstream:

1. The 4 Sages-owned subagent configs (developer, auditor, merger, git-expert) inherited lowercase keys from npm-upstream conventions; the 2 read-only types (Explore, Plan) used PascalCase to signal "read-only" in the visual roster.
2. `git-expert` was added in the original pi-subagents for a git-specific use case that the user's DAGs never actually needed. It survived because no one removed it.

The existing `resolveKey()` in `pi-subagents/src/agent-types.ts:67-74` already did case-insensitive matching, so the rename was a documentation/prose upgrade — not a runtime breaking change.

## Risks + watchpoints

- **ID-reuse disambiguation** — the `GC-2026-091` id was recycled from the prior session's plan→DAG→todo GC. The orphaned prior postmortem content was overwritten with this file's content; the prior work itself (`8ddfb24`) is still on main and is unaffected. Future GCs MUST avoid id collisions — `gen:gcdb` (not yet implemented) would catch this at synthesis time.
- **Case-insensitive resolver preserved** — `resolveKey()` continues to accept lowercase `developer`/`auditor` for backward compat. New code SHOULD use PascalCase; old call sites can be migrated opportunistically.
- **Catalog regeneration required** — any change to `default-agents.ts` Map keys or any entry in `pi-orchestrator/templates/agent-tool-description.md` MUST be followed by `bun run gen:catalog` and a commit of the regenerated catalogs. ## What worked

- **Bundling the registry rename with the git-expert removal** was the right call — both touch `default-agents.ts` and the agent-tool-description roster, so splitting them would have forced two passes through the same files.
- **Managed-worktree isolation per batch** (`sages/GC-2026-091/P1`-`P6` + `P5b`) let each phase land independently. The `--no-ff` merges preserved the per-batch history on main even after integration.
- **Case-insensitive `resolveKey()` retained** — backward compat with existing DAG YAMLs + the upstream npm package was the key constraint, and the resolver made the rename a documentation upgrade rather than a breaking change.
