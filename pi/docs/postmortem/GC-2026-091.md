# GC-2026-091 — Postmortem (post-hoc reconstruction)

## What happened

Subagent names registered inconsistently — the 5 default agents
(Developer, Reviewer, Merger, Explore, PlanCompiler) had a mix of
PascalCase canonical names and lowercase legacy aliases
(`developer` vs `Developer`, `auditor` vs `Reviewer`, `git-expert`
which was a never-shipped 6th agent). Path B's `workflow_run` needed
one canonical name per agent type for predictable dispatch; the
caller-side spelling had drifted away from the canonical registry
keys.

## Root cause

GC-2026-014 removed the `software-developer` legacy alias. After
that, additional lowercase aliases (`git-expert`, `auditor`) and
case-drift remained. Cross-package callers (pi-tasks workflow graph,
pi-orchestrator's subagent-control tool) passed type names with
mixed casing; the `resolveType` registry function silently case-folded
but emitted warnings on every lookup.

## Fix

Commit `d927939 merge(GC-2026-091): integrate subagent naming PascalCase
canonical + git-expert removal` brought 7 P-task commits:

- P1 (`b5488e6`): default-agents.ts rename + agent-frontmatter-verify
  fix + catalogs. Canonical names now `Developer`, `Reviewer`,
  `Merger`, `Explore`, `PlanCompiler`. The `git-expert` placeholder
  (never-shipped) deleted.
- P2-P5: case-insensitive runtime dispatch in
  `resolveType` (downstream / upstream); `AGENTS.md` / `SYSTEM.md` /
  `SKILL.md` updates to surface canonical names.
- P5b (`658e607`): close test-fixture sweep gap + wire
  case-insensitive resolver.

## Verification

Post-merge: all caller-side spellings pass through `resolveType`
without warnings. The `resolveType` registry function is the single
source of truth for casing; downstream code may use either spelling
but the canonical name is the registry key.
