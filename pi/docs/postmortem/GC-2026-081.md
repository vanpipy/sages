title: Expose todowrite + todowrite_compile + todowrite_progress in the orchestrator active toolset
severity: minor
---

## What happened

Added 3 new tools (`todowrite`, `todowrite_compile`, `todowrite_progress`)
to the orchestrator's `setActiveTools` policy. Pre-GC-081 these
tools existed in the runtime (registered by the orchestrator's
extension factory) but were not exposed to the LLM via
`setActiveTools`, so the LLM could see them in the prompt but not
actually call them.

## Root cause

`setActiveTools` is a denylist/allowlist policy that the orchestrator
uses to gate which tools the LLM can see. The 3 todowrite tools were
registered but not added to the allowlist, so they were effectively
hidden.

## Fix

Added the 3 tools to the orchestrator's `setActiveTools` allowlist.
Verified via the `session_start end-to-end via MockPi` test that
the LLM now sees them.

## Follow-ups

- Post-GC-2026-path-B-tracking, the todowrite tools are partially
  shadowed by the pi-tasks `TaskCreate` / `TaskList` / `TaskGet` /
  `TaskUpdate` / `TaskExecute` surface. The 3 todowrite tools are
  kept for backward compat.
- See `pi/docs/postmortem/GC-2026-100.md` for the personal_todowrite
  → agent_todowrite rename.
