# GC-2026-060 — auto-todowrite + todo reminder (root-agent only)

## What happened

Implemented the Sages-owned auto/dynamic todowrite capability modeled on
deepseek-harness: `TodoStateManager` (whole-list snapshot/diff/persist with a
root-only owner guard), the `sages_todo` LLM tool (sync/get/auto-plan from the
active DAG), the todo reminder builder (compact per-turn block + change
highlight + stale gentle/detailed thresholds), and extension listeners
(tool_call mirror of the built-in `todowrite`, before_agent_start injection,
input reset, turn_end stale advance). The todo list belongs to the ROOT agent
only; subagent sessions never see `sages_todo`, never fire root tool_call
listeners, and non-root owner files are rejected at deserialize.

Delivered as a 4-task serial DAG (T1 state engine → T2 tool+reminder → T3
extension wiring → T4 docs+gates). Final chain merged to main as `345b826`
(feat(todo): merge auto-todowrite + todo reminder). All 7 gate checks green,
1145 tests pass.

## Root cause (of the notable friction)

Two operational frictions surfaced, neither a code defect:

1. **Managed-worktree `reuse` refuses advanced branches.** The reuse contract
   pins the slot to its recorded `baseSha`; a branch advanced by commits (the
   normal outcome of a completed developer task) is refused. The serial-chain
   pattern "reuse the same slot" documented in SUBAGENTS.md therefore does not
   work as written once the first task commits.
2. **AF-001 report-format gap.** `orchestrator_audit`'s GC-2026-039 enforcement
   flagged all 4 developer tasks `castration/major` because the agents' final
   messages contained no parseable YAML block (status/deliverables/
   test_results). This is a report-format requirement the developer prompts did
   not explicitly demand; the audit REVISE verdict (score 60) reflects the
   mechanical gap, not deliverable quality — every SC was verified green and
   every task was CERTIFIED.

## Fix

1. **Serial-chain worktree pattern:** provision each subsequent task in a FRESH
   slot with `base_ref: <prior-branch>` (e.g. `base_ref: sages/GC-2026-060/T2`
   for T3), producing a clean linear chain with no cherry-picks. `mode: reuse`
   is only for re-entering an untouched slot. (Documented for the orchestrator
   SKILL as a follow-up.)
2. **YAML report blocks:** future developer/auditor dispatches should
   explicitly require a final ```yaml block (status / deliverables /
   test_results / open_questions / handoff_for_next_task) so the mechanical
   audit gate can verify deliverables.
