title: Expose aft_* + ctx_* tools in the orchestrator active toolset
severity: minor
---

## What happened

Added the 11 AFT tools (`aft_search`, `aft_outline`, `aft_zoom`,
`aft_callgraph`, `aft_inspect`, `aft_import`, `aft_refactor`,
`aft_move`, `aft_delete`, `aft_conflicts`, `aft_safety`) to the
orchestrator's `setActiveTools` allowlist. Also added 7 codebase
context tools (`mcp_detect_changes`, `mcp_query_graph`, etc.) to
the codebase-memory SKILL.

## Root cause

Pre-GC-086, the AFT + ctx_* tools existed in the runtime (registered
by their respective packages) but were not exposed to the LLM via
`setActiveTools`. The LLM had to know to look for them by name even
though they weren't in the visible tool surface.

## Fix

Added the 11 AFT + 7 ctx_* tools to the orchestrator's `setActiveTools`
allowlist. Updated the codebase-memory SKILL to document the
mcp_* tool surface.

## Follow-ups

- The AFT tools are now part of the standard tool surface the LLM
  sees. The codebase-memory SKILL is loaded on demand when the LLM
  uses an `mcp_*` tool.
- No new tests were added in this GC; the existing
  `session_start end-to-end via MockPi` test was extended to assert
  the AFT tools are in the setActiveTools output.
