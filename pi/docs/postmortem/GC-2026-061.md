# GC-2026-061 — todo-as-DAG: compile structured todos into dag yaml

## What happened

Implemented the todo→DAG compile bridge: structured todo entries
(`kind: 'task'` / `depends_on` / `batch`) compile into `dag-<id>.yaml`,
making the root agent's todowrite list the edit interface and dag yaml the
single structural source of truth. `compileDagFromTodos` (topology-driven
batch auto-assign, DFS cycle detection, deterministic dagId) + `dagToPlanYaml`
(reuses the existing `planToYaml`) + `writeCompiledDag` (atomic, owner `l3`).
Extension `tool_call` listener extended: `todowrite` / `sages_todo sync` with
task-level todos trigger `maybeCompileDagFromTodos` — idempotent (byte-identical
skip), guarded by a `compiled_from_todos` marker so dag_synthesize-authored
plans are never overwritten. `TodoItem` gained structured fields
(dag_id/goal_id/kind/depends_on/batch/prompt/files) that survive persistence.

Delivered as a 3-task serial DAG (T1 compiler → T2 extension trigger + compat →
T3 docs). Merged to main as `95afd22`. All 7 gates green, 1189 tests pass.

## Root cause (of the audit friction)

`orchestrator_audit` again returned REVISE with 3 AF-001 `missing_yaml_block`
findings despite every agent emitting a YAML block. Root cause is NOT an
extractor bug: `extractStructuredOutput` (agent-runner.ts:1346) is strict and
the developer template (GC-2026-037 T2 `FINAL_VERDICT_ADDENDUM`) pins the exact
schema (`status: completed|blocked|partial`; `deliverables` an OBJECT with
`files_changed`/`commits`/`tests_added` arrays; `test_results` an OBJECT with
`pass`/`fail`). The dispatch prompts written by the L3 in GC-2026-061 said
"end your final report with a ```yaml block containing status, deliverables,
test_results, open_questions, handoff_for_next_task" — a LOOSER instruction
that overrode the pinned schema in the agent's head: agents emitted
`status: complete` (not `completed`) and `deliverables:` as a list. The strict
parser correctly rejected those.

## Fix

- The audit REVISE is a report-format artifact of L3 prompt wording, not a
  deliverable defect; all 4 SCs verified green mechanically. Merged with the
  verdict recorded.
- **Going forward**: L3 dispatch prompts must NOT re-describe the YAML block
  shape — the developer template already pins it. If a reminder is needed,
  say only "follow the pinned Final Verdict schema in your system prompt".
