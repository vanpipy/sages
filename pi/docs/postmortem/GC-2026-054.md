# GC-2026-054 — Postmortem for GC-2026-053 + gen-gcdb improvements

> **Date:** 2026-08-20
> **Status:** Resolved
> **Severity:** minor

## What happened

GC-2026-053 (orchestrator self-feedback loop) shipped 4 commits
landed in `.pi/orchestrator/` and merged to origin. Before it could
be merged to main, the project's gcdb discipline required a
postmortem OR carve-out entry (§6 of AGENTS.md; enforced by
`bun run verify:gcdb`).

This GC adds the postmortem and regenerates `pi/docs/gc-index.md`
so the merge is mechanically unblocked. The postmortem documents
the L1 advisory extension + sages_reminder tool + 3 routine
templates, including the 2 self-corrections that came up during
execution (subagent worktree cwd, Type.Literal widening).

The implementation also fixed a latent bug in `gen-gcdb.ts`:
the script's `git log --grep='GC-' --format='%H %s'` only matched
commits with the GC ID in the SUBJECT, missing commits that
reference the ID only in the footer (`Refs: GC-...`).

## Root cause

Two separate issues:

1. **Postmortem missing.** GC-2026-053 merged to origin/sages/.../T1
   but the merge to main requires the postmortem per the project's
   gcdb discipline. The discipline was added in GC-2026-051, but
   the workflow for "postmortem for the just-shipped feature" was
   never automated — it requires a separate GC.

2. **gen-gcdb subject-only matching.** The script's regex search
   only checked commit subjects, not bodies. The project
   convention (per AGENTS.md) is `Refs: GC-2026-NNN` in the commit
   FOOTER, not the subject. As a result, GC-2026-053's four commits
   (`8b6a0ee`, `059a2cb`, `8149b3e`, `f4cd06a`) had GC-2026-053
   only in the footer, so gen-gcdb picked only `f4cd06a` (whose
   subject happens to mention the GC ID) and the index entry for
   GC-2026-053 became "runtime wiring smoke test (23 cases)" — a
   smoke test title, not the canonical feature title.

## Fix

Two commits in the same branch (`sages/GC-2026-054/postmortem`):

### 1. The postmortem itself

`pi/docs/postmortem/GC-2026-053.md` — 4-section template (What
happened / Root cause / Fix / Follow-ups). Follows the same
format as GC-2026-029 / GC-2026-031 / GC-2026-044 postmortems.

Severity tagged `major` (a structural feature was added, but no
production behavior was broken). Follow-ups documented as
GC-2026-054 (this), 055, 056, 057, 058.

### 2. gen-gcdb improvements

`pi/scripts/gen-gcdb.ts` — two changes:

a. **Body-aware scan**: use `git log --all --format='%H %s%n%b%n--END--'`
   so any commit that references `GC-YYYY-NNN` anywhere (subject
   OR footer) is picked up. The footer is the canonical place per
   AGENTS.md commit conventions.

b. **Title selection**: prefer the most recent commit whose subject
   starts with a primary Conventional Commits prefix (merge / feat /
   fix / refactor / perf) over test / docs / chore / style. The
   canonical title comes from the feature commit, not the trailing
   smoke-test commit.

### Side effects

- 5 previously-missed GCs (004, 011, 012, 021, 022) now appear in
  the index because they only referenced their GC ID in the body.
- Some old GCs (008, 015, 017, 035) have updated titles because
  the most recent primary/feature commit now wins over the original
  subject-only match.
- GC-2026-053 now correctly identifies its core implementation
  ('3 Sages routine templates...') instead of the smoke test.

`verify:gcdb` still passes (postmortem coverage trivially satisfied
when goal contracts aren't in the worktree's `.pi/orchestrator/`).
