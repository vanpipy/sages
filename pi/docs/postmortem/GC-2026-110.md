## What happened

Closed the **deploy-time** side of the session-runtime fragility
that has now hit **four** consecutive Sages GCs
(`GC-2026-task-feeding-and-decomposition`, `GC-2026-108`,
`GC-2026-109`, and would have hit any future workflow_run GC in
this same session).

`install.sh` already runs the `verify:extension-load` smoke test
at the end of `install()` (line 2232 pre-FU1b) — the half of FU1b
that surfaces "extensions fail to load silently" was already in
place from GC-2026-extension-load-verify. What was missing:

1. **The three end-of-install gates were scattered.** `verify_all_critical_install_deps`,
   `verify_package_existence`, and the extension-load smoke test
   were three separate `|| { ...; exit 1; }` blocks. A future
   fourth gate would mean another `|| { ...; exit 1; }` block, with
   no shared "what does failure look like" treatment.
2. **The smoke test had no banner.** It printed `==> Verifying
   extension load via jiti (catches silent fail-soft)...` but no
   explicit "POST-INSTALL SMOKE TEST" framing, and no PASS/FAIL
   summary line at the end. Easy to miss in install's verbose output.
3. **No escape hatch for fast iteration.** Power users who know
   the install is sound had no way to skip the smoke test without
   commenting out the relevant block.

The fix:
- Extract the three gates into `run_post_install_gates()` (returns
  the count of failed gates). `install()` calls it once with a
  shared "Install completed but post-install verification failed.
  Re-run with --force to repair" recovery block.
- Add a `--no-smoke` flag (parsed in `main()`) that sets
  `$SMOKE=false`. Gates 1 and 2 still run; gate 3 is skipped.
  Documented in the `usage()` block + the script header comment.
- Add explicit `==> POST-INSTALL SMOKE TEST` banner before the
  smoke test, plus a `==> POST-INSTALL SMOKE TEST: PASS|FAIL`
  summary line after.
- Update the `usage()` block to document `--no-smoke`.

## Why this design

The "atomic" property of install.sh was already at the **gate
level**: any partial-failure state would be caught by one of the
three gates and exit 1 with a clear recovery command. The
refactor doesn't change that contract — it consolidates the gates
into one place and surfaces the smoke test with explicit framing.

True transactional rollback (snapshot `~/.pi/`, do install, restore
on failure) was considered and rejected:

- **Cost**: every install would double its I/O (snapshot + restore).
  For a 5-10s install that's a real overhead.
- **Failure mode is rare**: the three gates catch every observed
  failure mode. Rolling back to "before install" is unnecessary
  friction when the failure is already detected and recovery is
  one re-run away.
- **Recovery is cheap**: `bash $0 --force` re-runs the whole
  install. The `is_*_installed` guards skip already-installed
  pieces. Most re-installs complete in <1s.

The smoke test is `--no-smoke`-skippable because power users
iterating on orchestrator changes don't need the 200-500ms jiti
load on every iteration. Gates 1 and 2 stay because they catch
real bugs (missing node_modules, missing dir) that --sync-only
specifically does not catch.

## What broke / what we had to fix mid-implementation

- **Test design (1st cut): the `SMOKE=false` test created a Promise
  that never resolved.** The behavioral test initially asserted
  the function was "still pending" after 50ms, but bun waits for
  every Promise to resolve before exiting the test process. Fixed:
  rewrote the disable test to fire all three phases (implement /
  review / merge) after a 50ms delay and assert `status: success`.
  This is the right test — it verifies "watchdog is off" by
  observing the success path complete, not by waiting for bun
  timeout.
- **Sandbox sanity check: `LOCAL_REPO_ROOT` must be set.**
  install.sh's sanity check (line 84) requires the 4 peer dirs at
  `$LOCAL_REPO_ROOT/{pi-orchestrator,pi-codebase-memory,...}`.
  The test sandbox has its own `pi-orchestrator/scripts/` but not
  the 4 peer dirs. Fixed: the test sets `LOCAL_REPO_ROOT` env var
  to the real repo path. Sourced the truncated install.sh (no
  `main "$@"` call) so the install flow doesn't actually run.
- **2 existing test cases in `install-package-existence.test.ts`
  pinned the OLD wiring pattern** (`verify_package_existence ||
  { ... }` inside `install()`). The refactor moved that into
  `run_post_install_gates()` with the new wiring
  (`if ! run_post_install_gates; then ...; fi`). Updated both
  tests to pin the new pattern. The functional behavior
  (failure → exit 1 with recovery message) is preserved.
- **`&>/dev/null` redirected the banner into /dev/null.** The
  `SMOKE=true` test snippet used `run_post_install_gates
  &>/dev/null` to silence the function's output, but the
  assertion was looking for the banner text. Fixed: use
  `2>&1` instead (redirect only stderr to stdout, keep stdout
  visible for the assertion).
