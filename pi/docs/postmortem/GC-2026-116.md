## What happened

Two long-standing pre-existing failures had been carried as "known
18 + 20 failures" across the whole task-feeding work. Neither was
caused by that work, but they masked real regressions and made the
suites unreliable as a signal. This GC fixes both.

### Failure 1 — 18 pi-tasks failures: cross-file `vi.mock` leak

`tasks-config.test.ts` failed 18/18 when run as part of
`bun test ./test`, but passed 18/18 in isolation. The failure was
`expect(loadTasksConfig(cwd, agentDir)).toEqual({})` receiving
`{taskScope: "memory"}`.

Root cause: 7 test files used the pattern

```ts
const config = { current: {} as Record<string, unknown> };
vi.mock("../src/tasks-config.js", () => ({
  loadGlobalTasksConfig: () => ({ ...config.current }),
  loadTasksConfig: () => ({ ...config.current }),
  saveTasksConfig: () => {},
}));
```

Under bun:test, `vi.mock` factories **leak across test files** in
the same invocation. The first file to register a factory keeps it
active for every later file, and the factory returns its own
closure's `config.current` regardless of the `agentDir` argument.
`tasks-config.test.ts` (which does NOT mock and needs the real
module to read temp files) therefore saw whichever file's
`config.current` was set most recently — typically
`{taskScope: "memory"}` from `task-create-details.test.ts` or
`store-scope.test.ts`.

Verified with a minimal repro:

```
bun test ./test/task-create-details.test.ts   # 3 pass
bun test ./test/tasks-config.test.ts          # 18 pass
bun test ./test/task-create-details.test.ts ./test/tasks-config.test.ts
                                              # 3 pass, 18 fail
```

**Fix**: replace the mock pattern with a real-file fixture
(`pi-tasks/test/helpers/tasks-config-fixture.ts`) exposing
`installTasksConfig(config)` / `uninstallTasksConfig()`. The fixture
writes a `tasks-config.json` to a per-test temp dir and sets
`PI_CODING_AGENT_DIR` — which `getAgentDir()` consults **before**
`os.homedir()`. That ordering matters: `os.homedir()` caches its
result from `test/setup.ts`'s scratch HOME at module-load time, so
setting `HOME` in a test body has no effect.

No `vi.mock("../src/tasks-config.js", ...)` remains, so there is
nothing left to leak. All 7 files were converted.

### Failure 2 — 20 pi-orchestrator failures: stale symlink

`pi-orchestrator/node_modules/@sages/pi-tasks` was a broken symlink
to a bun cache path (`…/node_modules/.bun/@sages+pi-tasks@file+pi-tasks+e41bd692c693cf62/…`)
that no longer existed. The orchestrator's `verify:catalog` and
`GC-2026-073 smoke` tests import pi-tasks transitively and errored
with `Cannot find module '@earendil-works/pi-tui'` etc.

**Fix**: repoint the symlink at the real source
(`/home/leroy/Project/sages/pi-tasks`). The suite went from 23
failures to 0.

### Failure 3 — latent typecheck error

Once pi-tasks' suite ran clean, `bun run typecheck` surfaced
`src/index.ts(1207,27): error TS18048: 'task' is possibly 'undefined'`
in the `TaskStop` tool (introduced by GC-2026-113's `subagentId`
lookup, where `task` is `store.get(resolvedId)` which can return
`undefined`). Fixed with `task?.status`.

## Why the leak was so persistent

The `vi.mock` pattern looked correct. The `vi-shim.ts` docs even
say `vi.hoisted` "is equivalent" to a plain top-level const under
bun:test — which is true, and is exactly why hoisting does not
help: the problem is not the closure, it is that the factory
**registration** is shared across files. The shim does not provide
`vi.unmock` or a working `vi.importActual` (both tried and
rejected), so there was no way to isolate the consumer side. The
only robust fix was to stop mocking the module at all.

Attempted and rejected along the way:

- `vi.hoisted(() => …)` — the shim's `vi.hoisted` is `fn()`; the
  closure is still per-file but the factory still leaks.
- `vi.unmock("../src/tasks-config.js")` — `vi.unmock is not a
  function` (not implemented by the shim).
- `vi.mock(…, async () => await importOriginal(...))` — hangs
  bun:test indefinitely (the shim's `importOriginal` does a dynamic
  `import` that deadlocks when re-entered from a mock factory).

## Follow-ups

- **pi-subagents has 5 pre-existing failures** unrelated to this
  work (the suite was not touched). One visible name:
  `reviewer.ts's rendered prompt contains the current
  DEFAULT_BUCKET_TIMEOUTS_MS.read value`. Filed for a separate GC.
- **`vi-shim.ts` could grow a real `vi.unmock`** so future tests
  have an escape hatch. Not needed now that the mock pattern is
  gone; filed as a nicety.
- **`os.homedir()` caching** is a footgun for any test that wants
  to redirect the agent dir. The new fixture documents the
  `PI_CODING_AGENT_DIR` workaround; consider hoisting that note
  into `test/setup.ts`.
