## What happened

A post-GC-2026-115 audit of the task-feeding pipeline (`./pi-orchestrator/` × `./pi-tasks/`) flagged finding **F1 (major)**: `pi-tasks/src/decompose-cascade.ts` (201 LOC) was dead production code after GC-2026-114 FU3 unified every task type's cascade through `registerTaskFeeder`.

Specifically:

1. **`registerDecomposeCascade` was imported but never called.** `pi-tasks/src/index.ts:35` imported the function; no production site invoked it. Bun/TypeScript didn't complain because import side-effects are zero.
2. **`'decompose:spawn'` event was emitted with no listener.** `materializeDecomposeChain` (now `pi-tasks/src/index.ts:443`) still emitted the event after the feeder's spawn — but the listener that consumed it lived only in `decompose-cascade.ts`, which was never wired. The event was a no-op in production.
3. **Stale comment block referenced a non-existent function.** `pi-tasks/src/index.ts:474` had a comment mentioning "spawnDecomposeTask" — that function was never defined; it was a GC-2026-114 pre-FU3 naming leftover.
4. **The test file was misnamed.** `pi-tasks/test/decompose-cascade-e2e.test.ts` is a unit test of the cascade module, not an e2e test. Its 5 test cases covered the now-dead module's behavior — so they tested a path that production code no longer executed.

The module + test file accumulated a total of ~410 LOC that exercised no production behavior. New contributors reading the code would see `registerDecomposeCascade` referenced (via the import) and the `decompose:spawn` event (via the emit) and assume there was a listener; the cognitive load was real even though the runtime was correct.

The audit explicitly listed this as the only major finding (F2-F6 were minor / nice-to-have). The user requested this cleanup as the canonical P0 fix.

## Root cause

The FU3 cleanup (GC-2026-114) was itself a merge of three earlier GCs (108 / 113 / 114) executed across multiple sessions. The postmortem for GC-2026-114 explicitly noted:

> The decompose-cascade.ts file is deleted; its `decomposeAgentMap`, `cascadeSpawn` filter, and three listeners (`decompose:spawn`, `subagents:completed`, `subagents:failed`) are gone.

— but the actual file was kept in the source tree with the `registerDecomposeCascade` function still exported, because the 60+ test fixture updates weren't shipped in the same GC. The test file `decompose-cascade-e2e.test.ts` imported the function and exercised it as a unit test, so removing the file in 114 would have left the test suite red.

When the test fixtures were finally adapted to the feeder model (GC-2026-112 Phase 2a), `decompose-cascade-e2e.test.ts` was no longer required for any production wiring — but it continued to exist and pass as a unit test of a module that was no longer in the graph.

## Fix

1. **Delete `pi-tasks/src/decompose-cascade.ts`** (201 LOC) — no production callers.
2. **Remove `import { registerDecomposeCascade }` from `pi-tasks/src/index.ts:35`**.
3. **Remove `pi.events.emit("decompose:spawn", ...)` from `materializeDecomposeChain`** (formerly line 443) — no listener existed to consume it.
4. **Update the stale comment block** (formerly line 474) to accurately describe the post-cleanup wiring: decompose-chain tasks flow through `feeder.cascadeSpawn` (which walks all pending feedable tasks with satisfied blockers), the dedicated module is gone, and `decompose:spawn` is no longer emitted.
5. **Replace the test file**: delete `pi-tasks/test/decompose-cascade-e2e.test.ts` (5 cases against the dead module) and write `pi-tasks/test/task-feeder-decompose-cascade.test.ts` (5 cases against the unified feeder, using the production cascade path).

The new test mirrors the production wiring: `materializeChain` builds T1 + R1 + T2 + T3 with `createOrchestratorTaskWithReview` / `createOrchestratorTask`, then `feeder.maybeAutoSpawn(T1)` kicks off the chain. Every assertion is via the feeder's listener (`subagents:completed` / `subagents:failed`), not the now-deleted module. The test explicitly documents this in its header:

> The test deliberately does NOT call `registerDecomposeCascade`, which no longer exists.

- `pi-tasks/src/materializeDecomposeChain` behavior — only the dead `decompose:spawn` emit was removed; the spawn itself (via `feeder.maybeAutoSpawn(t1)`) is unchanged.
- `pi-orchestrator/` — no orchestrator-side changes needed.
- The cascade contract: T1 → T2 → T3 → R1 still runs serially with blockedBy satisfaction gating.
