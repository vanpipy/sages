# GC-2026-092 — Postmortem (post-hoc reconstruction)

## What happened

Sages users wanted to pin per-agent-type model defaults (e.g. "always
use MiniMax-M2 for Reviewer, MiniMax-M3 for Developer") without
reaching into the orchestrator's runtime config. The pre-existing
`subagents.json` already supported `model` (single global default);
adding a `defaultModelsByType` map extended the override surface.

## Root cause

`subagents.json` schema was single-string for `model`. Each agent type
needed its own override to handle the model-class specialization
that Sages' prompts assumed (Reviewer = cheaper model, Developer =
capable model, Explore = cheapest). A single global default forced
either overprovisioning or underprovisioning.

## Fix

Commit `1b365af merge(GC-2026-092): integrate subagents.json
#defaultModelsByType per-type model overrides` brought 5 commits:

- P1 (`ed359ca`): `SubagentsSettings` extension + new
  `settings-default-models-by-type.ts` helper module. Sanitization
  drops empty keys / non-string values silently. `applySettings()`
  wires the new `setDefaultModelsByType` callback.
- P2 (`87084bd`): `pi-subagents` wire per-type `defaultModelsByType`
  into the agent-runner resolution chain.
- P3-P4: docs in `subagents.json` template + memory #96 update.

## Verification

`defaultModelsByType` in `subagents.json` flows through to
`getDefaultModelByType(type)` (case-insensitive lookup, mirrors the
existing `networkAllowedByType` / `durationDefaultsMs` precedence).
Post-merge docs (subagents.json template + memory #96) document the
new field.
