# GC-2026-092 — subagents.json#defaultModelsByType

## What happened

The model resolution chain in pi-subagents had two layers:

1. **Hardcoded per-agent `model:`** in `pi-subagents/src/default-agents.ts` (e.g. `Developer`/`Auditor` pin `MiniMax/MiniMax-M3`, `Plan` pins `anthropic/claude-haiku-4-5` with `thinking: minimal`).
2. **Global `defaultProvider`/`defaultModel`** in pi's `~/.pi/agent/settings.json`.

There was no project-level way to **override** the hardcoded defaults without editing the source. Users who wanted to swap one agent's model (e.g. switch the developer to `anthropic/claude-opus-4`) had to fork the package.

GC-2026-092 adds a per-type override map to `subagents.json#defaultModelsByType` that slots into the resolution chain between the hardcoded `AgentConfig.model` and the global `settings.json` default. Keys are the canonical PascalCase agent names (`Developer`, `Auditor`, `Explore`, `Plan`, `Merger`); values are `provider/model` strings.

## Root cause

The `AgentConfig.model` field was set at registration time in `default-agents.ts` and frozen at package build time. The `settings.json#defaultProvider`/`defaultModel` fallback only covered the case where no model was set at all — not the case where a model was set but a project wanted a different one.

The resolution chain was deliberately thin (two layers) because it kept the package config-light. As soon as users needed project-level overrides, the chain needed a third slot.

## Fix

A new optional field `defaultModelsByType?: Record<string, string>` on the `SubagentsSettings` interface. Read via a new helper module that mirrors the existing `settings-default-model.ts` pattern (project + global precedence, mtime-driven stat-cache invalidation).

### Bug found + fixed mid-flight

The initial `readField(project) ?? readField(global)` implementation in `settings-default-models-by-type.ts` only picked one map or the other — it didn't merge. The "merges project-overrides-global when project and global both have the field" test caught this. Fixed by spreading `{...global, ...project}` to mirror the `loadSettings()` convention in `settings.ts:84`. Caught at RED in P3, fixed before commit.

## Risks + watchpoints

- **Per-type override is opt-in** — users without `defaultModelsByType` in their config fall through to the existing hardcoded `AgentConfig.model` (or `settings.json#defaultProvider/defaultModel` fallback). Migration is fully backward-compatible.
- **Resolution chain priority** — `Agent({ model: '...' })` per-call > `subagents.json#defaultModelsByType` per-type > `AgentConfig.model` hardcoded default > `settings.json#defaultProvider/defaultModel` global fallback. Per-call always wins.
- **Case-insensitive lookup** — `Developer` and `developer` both resolve; the helper normalizes the key before lookup. Future GC could ship a `dag_synthesize` lint that warns on lowercase keys (analogous to GC-2026-091's T3 follow-up).
- **Stat-cache invalidation** — same mtime-driven pattern as the existing `settings-default-model.ts` helper. Filesystem with coarse mtime granularity may need a nudge via `utimesSync` (handled in the test).
- **Empty-value drop** — sanitize drops empty-string values silently. The helper does the same. Test `drops empty-string values and returns the remaining map` pins this contract.

## Follow-ups

1. **T1 (suggested)** — extend the GC-2026-014 `defaultProvider`/`defaultModel` fallback chain with a per-call `Agent({ defaultModel: '...' })` override, so users can override the model for a single subagent invocation without touching `subagents.json`. Low priority; current per-type override covers the common case.
2. **T2 (suggested)** — `verify:gcdb` should cross-check that the `goal-{id}.yaml` title matches the `pi/docs/postmortem/{id}.md` frontmatter title (analogous to GC-2026-091's T2). Today the verify gate is content-blind — the ID-reuse collision in that prior GC went undetected because the gate only checks file existence.
3. **T3 (suggested)** — case-insensitive resolver: when `Developer` and `developer` both resolve to the same value, the dispatcher's log line should print the canonical key (PascalCase), not the user's lowercase form. Currently it prints whatever the user typed.

## What worked

- **Mirroring the existing `settings-default-model.ts` pattern** — the mtime stat-cache, project-overrides-global precedence, `process.env.PI_CODING_AGENT_DIR` redirect, and `readField` validation all copied from the proven sibling helper. Code review was straightforward because the new helper looked identical to its neighbor.
- **RED→GREEN test pinning the merge contract** — the "merges project-overrides-global" test caught the `??`-vs-spread bug at RED. Without that test, the bug would have shipped as a silent project-overrides-global inconsistency.
- **Subagent dispatch NOT touched** — the per-type override lives in `subagents.json`, not on `AgentConfig` or `Agent()`. Users override via config; callers don't have to thread a `defaultModel` parameter through every dispatch. Anti-goal SC9 pinned this (the field does NOT appear on `AgentConfig` or `AgentInvocation`).
