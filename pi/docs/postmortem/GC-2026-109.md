## What happened

Closed the **runtime** side of the session-runtime fragility that
has now hit **three** consecutive Sages GCs
(`GC-2026-task-feeding-and-decomposition`, `GC-2026-108`, and would
have hit any future workflow_run GC in this same session).

`workflow_run` emits `workflow:start` on `pi.events`. If the active
session has no listener for that event (e.g. `pi-tasks` /
`pi-subagents` extensions are not registered in `~/.pi/settings.json`),
the Promise stays pending until the harness timeout
("No result provided"). The fix: a watchdog timer inside the
Promise constructor that detects "no progress" within
`options.timeout_ms` (default 10000) and rejects with a clear,
actionable error.

The error class is `WorkflowRunStartTimeoutError`:

```ts
export class WorkflowRunStartTimeoutError extends Error {
  override readonly name = "WorkflowRunStartTimeoutError";
  readonly code = "WORKFLOW_START_TIMEOUT";
  constructor(goalId, workflowId, timeoutMs, message) { super(message); }
}
```

The error message names the goal_id, workflow_id, and the fix:

> workflow_run for goal GC-XXX (workflow_id: wf-XXX) did not
> receive any workflow:phase-complete event within 10000ms. This
> usually means the pi-tasks and/or pi-subagents extensions are
> not registered in the active session. Fix: run
> pi-orchestrator/scripts/install.sh and restart pi.

The watchdog is cancelled the moment any `workflow:phase-complete`
event for the matching `workflow_id` arrives. Existing failure
paths (`subagents:failed`, `max_fix_iterations` exhaustion,
`NEEDS_CLARIFICATION` pause) are unchanged.

## Why this design

The original failure mode is event-bus fragility: `workflow_run`
emits an event, the active session may or may not have a listener,
and there's no in-band signal to tell the producer that no one
heard. The fix is a watchdog because:

- **No new event channels needed**. Adding `sentinel:ping/pong`
  would have introduced a new event-bus protocol surface that
  every extension would need to opt into. The watchdog is local
  to `workflow_run` and only inspects an existing channel
  (`workflow:phase-complete`).
- **No in-process fallback**. A "self-registration" fallback that
  mirrored pi-tasks's `buildStaticWorkflowGraph` would couple
  pi-orchestrator to pi-tasks internals. The event-bus
  architecture is intentional (pi-orchestrator emits;
  pi-tasks handles the rest). A clear error + manual takeover
  honors the soft-mode contract without breaking the boundary.
- **Actionable error > silent retry**. The user immediately knows
  what's wrong and how to fix it. A silent retry would hide the
  problem and waste a session.

The watchdog duration is 10 seconds — long enough for slow
extension loaders, short enough to not be annoying. Configurable
via `options.timeout_ms` (set to 0 to disable; useful for tests
that drive the cascade out of band).

## What broke / what we had to fix mid-implementation

- **Test design: `timeout_ms: 0` test originally created a Promise
  that never resolved.** First cut of the disable-watchdog test
  just created a harness.run() Promise and asserted it was still
  pending after 50ms. The test passed the assertion, but bun
  waited for the pending Promise to resolve before exiting —
  test process hung indefinitely. Restructured: the disable test
  now fires all three phases (implement / review / merge) after
  a 50ms delay and asserts the Promise resolves as `status: success`.
  This is the right test because it verifies "watchdog is off" by
  observing the success path complete, not by relying on bun's
  test-timeout to detect the missing watchdog.

- **Pre-commit hooks fired during `git commit`**. The husky
  pre-commit hook runs `orchestrator:typecheck` + `orchestrator:test`
  in a single shell. The first attempt also prepended the `cd
  pi-orchestrator` from a previous bash call, which produced a
  confusing log. The actual commit only contains 2 files; the
  pre-commit hook output is unrelated to the diff. Verified via
  `git show --stat HEAD` that the commit is clean.

- **Initial watchdog fired before Promise wiring was complete.**
  The watchdog is set up after `let ev_findings_count: ...;` but
  the `pi.events.on("workflow:phase-complete", ...)` registration
  happens further down. This is fine — the timer is created
  before the event-listener wiring only matters if the timer
  fires during the synchronous block between the two. In practice
  the synchronous block is microseconds; the timer never fires
  there. The test (54ms timeout) confirms the wiring is correct.

The 3 new watchdog tests are:

1. `rejects with WorkflowRunStartTimeoutError when no
   workflow:phase-complete arrives within timeout_ms` — sets
   `timeout_ms: 50`, fires no events, asserts the Promise rejects
   with a message mentioning goal_id, pi-tasks, and install.sh.
2. `does NOT fire the watchdog when a workflow:phase-complete
   arrives within the window` — sets `timeout_ms: 200`, drives
   the cascade normally, asserts `status: success`.
3. `timeout_ms: 0 disables the watchdog — late events still
   resolve` — disables the watchdog, waits 50ms, then drives the
   cascade; asserts `status: success`. Verifies the escape hatch.

## Follow-ups

- **FU1b** (next GC): `pi-orchestrator/scripts/install.sh`
  becomes atomic + adds a post-install smoke test. The companion
  deploy-time fix: closes the gap that allowed the fragility to
  occur in the first place (the install script's registration
  silently dropped in this session). Two candidate sub-fixes
  within FU1b:
  - `install.sh` becomes a single atomic transaction (write all
    `settings.json` + `extensions/` files in one go; if any
    step fails, roll back the partial state).
  - `install.sh` adds a post-install smoke test that emits
    `sentinel:ping` and verifies `sentinel:pong` from each
    registered extension within 5s.
- **FU0** (filed in `2026-10-08-user-task-feeder.md`): the
  Phase 2 producer refactor + 60+ test fixture updates that
  completes the unification. Now that FU1a is in place, future
  workflow_run GCs that run in unconfigured sessions will fail
  fast (≤10s) instead of hanging — making manual takeover
  feasible without burning 30s of session time per attempt.
- **FU2** (filed earlier): persist `agentTaskMap` across session
  restarts.
