# GC-2026-093 — Postmortem (post-hoc reconstruction)

## What happened

The plan agent registered as `Plan` (lowercase, single-word) was
inconsistent with the other 4 default agents (Developer / Reviewer /
Merger / Explore — PascalCase compound words). The LLM-facing roster
treated `Plan` as a one-word verb, which both confused callers and
broke the case-insensitive resolver convention.

## Root cause

The `Plan` agent predated GC-2026-091's naming convention. The
registry had two stable keys (`Plan` and `PlanCompiler`) but only
the legacy `Plan` key was the canonical; `PlanCompiler` was an
informal alias.

## Fix

Commit `2ce825a merge(GC-2026-093): integrate Plan → PlanCompiler
subagent rename` brought:

- P1 (`5b9027d`): dual-key Map entry — `["PlanCompiler", PLAN_AGENT]`
  (canonical) + `["Plan", PLAN_AGENT]` (legacy alias). AgentConfig
  renamed to `name: "PlanCompiler"`.
- P2 (`4d7410b`): accept PlanCompiler in AgentType unions + dispatch.
- P3 (`f4e2b42`): surface PlanCompiler in template + roster + skill.
- P4 (`5f38398`): remove alias parentheticals from PlanCompiler
  LLM-facing descriptions.
- Post-merge docs (`a2abf1c`): postmortem + memory #96 + gc-index entry.

## Verification

5 new tests pin the rename (canonical key, legacy alias,
same-object invariant, name/displayName fields). Existing Plan
runtime-config tests migrated to the "PlanCompiler config" describe
block.
