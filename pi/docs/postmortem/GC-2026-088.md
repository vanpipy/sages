# GC-2026-088 — Verifier path offset bug

## What happened

`pi-orchestrator/scripts/verify-catalog.ts` `verifyCookbookPostmortemConsistency` (lines 259-260, 310) and `pi-orchestrator/scripts/verify-gcdb.ts` `GOAL_DIR` / `POSTMORTEM_DIR` / `GC_INDEX` (lines 31-33) defined defaults via `PI_ROOT = join(__dirname, "..")` which resolves to the `pi-orchestrator/` package root.

But the institutional docs (`gc-index.md`, `postmortem/`) live at `<repo>/pi/docs/`, and orchestrator state (`goal-*.yaml`, `dag-*.yaml`, `audit-state-*.yaml`) lives at `<repo>/.pi/orchestrator/` — **one level up** from `pi-orchestrator/`.

Both verifiers therefore silently passed without ever inspecting real coverage:

- `bun run verify:catalog` reported `gc-index.md + postmortem dir both absent — institutional coverage suspended (no orphan postmortems)`. The "OK" status was a **false positive** — the gate never looked at the right path.
- `bun run verify:gcdb` reported `no goal contracts in .pi/orchestrator/; coverage trivially satisfied`. Same false positive.

A GC with a missing postmortem would have been silently accepted as covered.

## Root cause

Both `verify-*.ts` scripts reused the same `PI_ROOT` constant that `gen-catalog.ts` uses. `gen-catalog.ts` correctly uses `PI_ROOT` (catalogs live under `pi-orchestrator/catalogs/`), but the two path-checking scripts wrongly reused it for **repo-root** paths.

The other `verify-*.ts` scripts (`verify-isolation-modes`, `verify-namespace-ownership`, `verify-soft-mode-mental-model`) correctly use `PI_ROOT` because their scanned source files live under `pi-orchestrator/`. They were unaffected.

## Fix

6 line edits, walking `..` at each affected default:

```diff
# verify-catalog.ts
- gcIndexPath: string = join(PI_ROOT, "docs", "gc-index.md"),
- postmortemDir: string = join(PI_ROOT, "docs", "postmortem"),
+ gcIndexPath: string = join(PI_ROOT, "..", "pi", "docs", "gc-index.md"),
+ postmortemDir: string = join(PI_ROOT, "..", "pi", "docs", "postmortem"),

# verify-catalog.ts line 310 (cookbook link resolution)
- const abs = join(PI_ROOT, "docs", tail);
+ const abs = join(PI_ROOT, "..", "pi", "docs", tail);

# verify-gcdb.ts
- const GOAL_DIR = join(PI_ROOT, ".pi", "orchestrator");
- const POSTMORTEM_DIR = join(PI_ROOT, "docs", "postmortem");
- const GC_INDEX = join(PI_ROOT, "docs", "gc-index.md");
+ const GOAL_DIR = join(PI_ROOT, "..", ".pi", "orchestrator");
+ const POSTMORTEM_DIR = join(PI_ROOT, "..", "pi", "docs", "postmortem");
+ const GC_INDEX = join(PI_ROOT, "..", "pi", "docs", "gc-index.md");
```

No helper introduced — minimal blast radius.

### `verify-gcdb-path.test.ts` (5 tests after trimming flaky static checks)

The tests write a uniquely-named fixture file (`GC-2026-088-PATH-FIXTURE`) to the repo-root `.pi/orchestrator/` in `beforeAll`, then auto-clean in `afterAll`. Cost: brief modification of orchestrator state dir, acceptable for a test.

## Discovered during fix

1. **Agent's test fixture had wrong paths** — assumed `<repo>/docs/gc-index.md` but actual is `<repo>/pi/docs/gc-index.md`. Fixed test constants + production code defaults to use the correct `..pi/docs/...` geometry.
2. **Agent left 2 flaky "static check" tests** — checked `existsSync(BUGGY_DEFAULT_GOAL_DIR) === false` which depended on test env state (worktree had `.pi/orchestrator/` from prior GCs). Removed; the behavior-pinning tests are sufficient to prove the fix.

## Follow-ups

None — the `..pi/...` geometry is local to 2 scripts and doesn't drift. Future orchestrator tooling that needs repo-root paths should use the same `join(PI_ROOT, "..", "pi", "...")` pattern.
