# GC-2026-062 — cwd-relative resource resolution broke global extension load

> **Date:** 2026-08-21
> **Status:** Resolved
> **Severity:** blocker

## What happened

Launching `pi` from any directory other than the repo root crashed at
extension load:

```
Error: Failed to load extension "/home/leroy/.pi/packages/sages/src/extension.ts":
  Failed to load extension: ENOENT: no such file or directory,
  open '/home/leroy/pi/profiles/standard.yaml'
```

`sages` is a **global** pi extension installed at `~/.pi/packages/sages`
and loaded from whatever cwd the user happens to be in. Three modules
resolved runtime resources relative to `process.cwd()` (or a
machine-specific path), so they only worked when the cwd happened to be
the sages repo checkout:

- `pi/src/profile.ts` — `BUILTIN_PROFILE_DIR = "pi/profiles"` (cwd-relative).
- `pi/src/tools/orchestrator/subagent-registry.ts` — `resolve("pi/subagents/registry.yaml")`
  (cwd-relative; latent ENOENT on dispatch).
- `pi/src/tools/orchestrator/template-loader.ts` — a hardcoded
  `/home/leroy/.pi/packages/sages` entry plus a `NODE_ENV`/cwd heuristic.

Compounding the crash, the install scripts (`install.sh` / `.ps1` / `.bat`)
shipped only `skills` and `src` — the `profiles/`, `subagents/`, and
`templates/` resource dirs were **never installed**, so even a
module-relative loader would have nothing to load in a fresh install.

## Root cause

Two independent defects, both of the "global extension assumes it runs
from its own checkout" class:

1. **cwd-relative resource resolution** — the modules treated their
   bundled YAML/templates as if they were project-local files, resolving
   them against the session cwd.
2. **install-location guessing / hardcoded paths** — `template-loader.ts`
   guessed the package root from `HOME`, a wrong `/root` fallback, and a
   hardcoded author path, instead of asking the module where *it* lives.
3. **incomplete install package** — the install scripts' copy loops
   omitted the resource dirs the runtime needs.

## Fix

- `profile.ts` / `subagent-registry.ts` / `template-loader.ts` now resolve
  their bundled resources **module-relative** via
  `dirname(fileURLToPath(import.meta.url))` (the existing
  `sages-routines-install.ts` precedent). Legacy cwd-relative candidates
  are kept only as fallbacks; the hardcoded `/home/leroy` path is gone.
- `loadProfile()` degrades to an in-code `STANDARD_PROFILE` constant
  (sourced from `soft-mode.ts`'s shims, byte-identical to `standard.yaml`)
  with a single `console.warn` instead of throwing, so a missing/partial
  install can never crash the extension at module load.
- `template-loader.ts` `cwdFallbackSagesRoot()` is now gated on explicit
  `SAGES_DEV=1`; template resolution no longer depends on `process.cwd()`.
- `todo-state.ts resolveRepoRoot()` dropped a now-harmful `findSagesRoot()`
  special-case (dead pre-fix, active + wrong once the root became
  module-relative in dev).
- `install.sh` / `.ps1` / `.bat` copy loops now ship `profiles`,
  `subagents`, and `templates` alongside `skills` and `src`.
