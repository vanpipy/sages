# GC-2026-053 — Orchestrator self-feedback loop (L1 advisory + reminder tool + session routines)

> **Date:** 2026-08-20
> **Status:** Resolved
> **Severity:** major

## What happened

Sages had a strong **L2 advisory** layer (subagent message validator, 5 rules,
`advisoryFor` with dedup/cap/token-cap). The orchestrator (root LLM) had **no
equivalent** — no self-detection, no structural feedback when its own tool
calls drifted (re-synthesizing the same DAG, dispatching without auditing,
skipping over failed tasks, drifting out of goal scope, accumulating tool
calls without checking the audit).

The second gap was **bridgeability**: pi-routines (the routine subsystem)
fire user-message LLM turns via `pi.sendUserMessage`. The LLM can call
LLM-registered tools, but `pi.appendEntry` (the way to inject system
reminders) is an extension API method, not an LLM tool. Routines had no
way to surface system reminders — they could only output to the chat.

The third gap was **cross-session continuity**: `.pi/orchestrator/` had
state persistence from day one, but `session_start` didn't surface
in-progress DAGs, and `session_shutdown` didn't promote workflow state to
durable memory. Users who closed a session mid-DAG had to manually read
`audit-state-*.yaml` on the next start.

## Root cause

Three structural gaps, each with a different cause:

1. **L1 advisory absence** — the L2 pattern (`pi-subagents/src/agent-runner.ts:advisoryFor`)
   was architected for subagent **message text**, not orchestrator **tool-call
   history`. The orchestrator's own decisions never had a structural observer.

2. **Extension-API / LLM-tool impedance mismatch** — pi's API model has
   `pi.appendEntry` on the extension side and `registerTool` on the LLM side.
   The two sides don't share methods. The routine subsystem fires LLM turns
   but cannot reach extension API. No bridge tool existed.

3. **Lifecycle hooks underused** — pi-routines supports `hook: session_start`
   and `hook: session_shutdown` triggers with `once: daily` / `once: per_session`
   policies. Sages shipped 0 routine templates of its own. The pattern was
   available but unused.

## Fix

Three modules, one branch (`sages/GC-2026-053/T1`), 4 commits, 906 tests.

### 1. L1 advisory mirror (`pi/src/tools/orchestrator/l1-advisory.ts`)

A new module that mirrors the L2 `advisoryFor` pattern but operates on the
orchestrator's tool-call history. Five rules + per-rule fix directives:

| Rule | Severity | Trigger |
|---|---|---|
| `dag_resynth_loop` | major | Same `dag_synthesize` called > 2 times with same goal_id |
| `dispatch_no_audit` | critical | `task_dispatch` called but no `orchestrator_audit` |
| `transition_skip_failed` | critical | `task_dispatch` for a task whose dep is in `failed` state |
| `goal_drift_detected` | major | Tool input references paths outside the active goal's scope |
| `no_progress_no_audit` | major | > 10 tool calls without an `orchestrator_audit` |

Wired into `pi/src/extension.ts` via `pi.on("tool_call", ...)` — observes
every orchestrator tool call, computes findings, injects via
`pi.appendEntry("system", advisoryString)`. Severity ≥ major filter,
`alreadyAdvisedRules: Set` dedup, `ADVISORY_MAX_PER_DISPATCH=2` cap,
`ADVISORY_MAX_TOKENS=200` token cap — same shape as L2.

### 2. `sages_reminder` tool (`pi/src/tools/orchestrator/sages-reminder.ts`)

A new LLM-callable tool that wraps `pi.appendEntry` for system reminders.
This is the bridge between the LLM context (which can only call tools)
and the extension API (which exposes `appendEntry`).

Six reminder types, each with a default template:
`STALE_DAG`, `MERGE_GATE`, `COMPLETION_GATE`, `GOAL_DRIFT`,
`RESUME_REQUIRED`, `GENERIC`. Defensive: invalid types return
structured error (no throw); `appendEntry` failure surfaces as
structured error (no propagation). 43 new tests.

### 3. Three routine templates (`pi/templates/routines/*.json`)

User-installed via `/routine-install <name>`. Each is a JSON file
matching the pi-routines template shape:

- **`sages-session-wrap`** — `hook: session_shutdown, once: per_session` — writes `ctx_memory` entries for active DAGs
- **`sages-resume`** — `hook: session_start, once: daily` — surfaces in-progress summaries in chat + injects `RESUME_REQUIRED` reminder
- **`sages-watchdog`** — `pulse 5m, maxTicks 14400` — fingerprints `.pi/orchestrator/audit-state-*.yaml`, calls `sages_reminder({type: STALE_DAG})` on 15+ min stalls, self-deletes via `RoutineDelete` when no active DAGs

50 new tests cover JSON validity, trigger correctness, quiet-mode
contract, and template-specific invariants.

### 4. Smoke test (5 phases, 23 cases)

`pi/test/smoke/gc-2026-053.test.ts` exercises the actual extension
loader flow with a mock `pi` runtime. Covers: tool registration,
L1 advisory trigger conditions, sages_reminder end-to-end, routine
template parsing, and channel independence.

## Two self-corrections during execution

### 1. Subagent worktree cwd confusion (T1)

The first `Agent` dispatch (T1) for the L1 advisory hit the turn limit
without committing. Inspection showed the work landed in the main
`pi/` directory, not the managed worktree. The subagent's `cwd` was
the main repo, not the worktree slot. Work had to be **lifted from
main into the worktree** and committed there. Subsequent T2/T3 work
was done directly in the worktree by the orchestrator rather than
re-dispatching developer, which avoided the same issue.

**Cost**: ~10 min of recovery (file copy + git commit maneuvering).
**Lesson**: the worktree label says "managed worktree" but the
subagent's runtime cwd is not the worktree; the agent must `cd` to
the worktree explicitly. This is unobservable to the orchestrator's
goal contract unless a precondition check is added.

### 2. `Type.Literal` widening in `Type.Union` (T2)

The `sages_reminder` parameter schema used `Type.Union(...)` built
from `SAGES_REMINDER_TYPES.map((t) => Type.Literal(t))`. The `.map`
callback widened `t` from a literal to `string`, so `Type.Literal(t)`
became `Type.Literal<string>`, which produced the type `string` (not
the literal union). The result: `SagesReminderInput['type']` was
`string`, which defeated the closed-enum intent.

TS errors were `Type 'string' is not assignable to type 'never'` —
the typebox resolution collapsed to `never` because the indexing
chain stopped being a real Record. Fix: write the literals explicitly
(`Type.Literal("STALE_DAG")`, etc.) instead of `.map`-ing.

**Cost**: ~5 min of two typecheck iterations.
**Lesson**: when using `Type.Union` to build a closed-enum schema,
NEVER `.map` over an array of literals — explicitly enumerate them.
The compiler loses the literal-type information.

## Follow-ups

See the four-tier roadmap that emerges from this work:

1. **GC-2026-054 (this postmortem)** — docs-only, regenerates `gc-index.md`.
2. **GC-2026-055** — wire `sages-session-wrap` / `sages-resume` / `sages-watchdog`
   to auto-install on `session_start` (currently user-installed); add per-type
   fix directives to `sages_reminder` (mirror L2's `RULE_FIX_DIRECTIVES`); clean
   the 2 pre-existing `task-count threshold` warnings in `verify:soft-mode-mental-model`.
3. **GC-2026-056** — `verification_cmd` linter: actually run the SC's
   verification_cmd once during `goal_contract_create` to reject placeholder
   commands like `echo "yes"`.
4. **GC-2026-057** — goal lock / modification audit: detect when the LLM
   silently modifies `goal.yaml` to make SCs easier (anti-cheat).
5. **GC-2026-058** — audit verdict enforcement: when `orchestrator_audit`
   returns REVISE, block subsequent `task_dispatch` until the failure is
   acknowledged (machine-enforced, not LLM-discretion).

Three are explicitly designated "作业设计问题" (out of Sages scope):
tool-level timeouts, idempotent re-dispatch, file lock. These
belong to the runtime/harness layer, not the orchestrator.
