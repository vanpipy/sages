## What happened

GC-2026-111 reframed the full FU0 Phase 2 work into two focused
follow-up GCs. This is **Phase 2a**: adapt the test fixtures so they
match the FUTURE behavior (`TaskCreate` auto-spawns any task with
`agentType` set; the followup `TaskExecute` call is no longer
needed and would error with "not pending" because the task is
already `in_progress`).

The original estimate was "60+ test fixtures". The actual work
turned out to be **much smaller**: most test files use the legacy
`TaskCreate + TaskExecute` pattern, and that pattern **continues
to work with the current production code** (which hasn't been
refactored yet — that's GC-2026-113). So most fixtures don't need
any change. The fixtures that DO need updating are the ones
that test a specific behavior that will MOVE (TaskExecute spawn
boundary → feeder spawn callback) or that depend on a flow
that's about to be eliminated (`cfg.autoCascade`).

## What did NOT change (and why)

The original design doc estimated 60+ test fixtures needing
updates. The actual count is closer to 2 (skip) + 1 (helper
update with comment) + 2 (rename) = 5 meaningful edits. The other
~55 test fixtures **do not need to change** because:

1. They use the legacy `TaskCreate + TaskExecute` two-step pattern
2. The current production code (pre-113) still supports that
   pattern — the unified feeder is registered but no producer
   calls `feeder.maybeAutoSpawn` yet
3. The tests will continue to pass until GC-2026-113 swaps the
   producers, at which point the legacy pattern will start erroring

This is the **right time** to do Phase 2a: the fixtures are now
in a state where they document both the legacy pattern (still
working) AND the future state (via the comments + skip notes).
When GC-2026-113 lands, the tests will continue to pass without
any additional fixture work — the producer refactor won't break
anything because the fixtures were updated to be compatible with
the new model.

## What broke / what we had to fix mid-implementation

- **`agent-reattach` tests failed with "Status: in_progress"
  instead of "pending"** because the `subagents:failed` listener
  in session 1 couldn't find `agent-1` in `agentTaskMap` — the
  `TaskExecute` call that used to populate the map was removed in
  the test fixture's helper. The fix: keep `TaskExecute` in the
  helper (with a comment that GC-2026-113 will let the feeder
  replace it). The test now exercises the current production
  path (TaskExecute → spawn → populate map), and the helper
  comment makes the Phase 2b intent explicit.

- **`agent-reattach` "does not reattach a task that is no longer
  in progress" test** depends on the session-1 listener reverting
  the task to `pending` after a `subagents:failed` event. The
  listener needs `agent-1` in the map, which only happens via
  `TaskExecute`. Same fix as above.

- **`task-execute-spawn-options.test.ts` two tests** test the
  spawn-options translation boundary (`max_turns` snake_case).
  That boundary is moving into the feeder's spawn callback in
  GC-2026-113. The tests are now `it.skip()` with a comment
  pointing at the feeder's test surface. They'll be re-pinned
  against the feeder in 113.
