# GC-2026-090 — Shared `wrapRegisteredTool` helper

## What happened

GC-2026-089 hand-wrapped 8 orchestrator tools (`task_dispatch`, `dag_synthesize`, `goal_contract_create`, `orchestrator_audit`, `subagent_status`, `subagent_steer`, `subagent_abort`, `subagent_resume`) in identical try/catch + ToolResult shape boilerplate across 5 source files. The pattern was the same one GC-2026-085 caught in 2 different tools. Each `registerTool` call site hand-rolled the same logic — a maintenance trap.

The pattern recurred because there was no shared abstraction. New tools added in future GCs would inevitably forget the wrapper, causing the renderer to crash again.

## Root cause

No shared helper. Each `registerTool` site copy-pasted the GC-2026-089 wrapper logic (~25 lines × 8 sites = ~200 lines of duplication). Drift inevitable.

## Fix

Extract `wrapRegisteredTool(toolName, execute)` to `pi-orchestrator/src/registered-tool-wrapper.ts`. Replace the 8 inline wrappers with one-line callers:

```ts
execute: wrapRegisteredTool("subagent_status", (params) =>
  executeSubagentStatus(params as SubagentStatusInput),
),
```

The helper preserves GC-2026-089 semantics exactly:
1. **Awaits** the execute call (so async resolves before JSON.stringify)
2. **Pass-through** if `Array.isArray(result.content)` (legacy ToolResult shape)
3. **Wraps** in `{content: [{type: "text", text: JSON.stringify(result, null, 2)}], details: result}`
4. **Error block** on exception: `{content: [{type: "text", text: `${toolName} error: ${message}`}], details: {status: "error", error: message}}`

## SC9 discrepancy: aft_inspect duplicate count

The goal contract SC9 expected `aft_inspect duplicates` count to drop from 1680 → ≤1580 lines (≥100 line reduction). In practice the count stayed at **1680 lines**.

**Why**: `aft_inspect`'s duplicate detection operates on text similarity thresholds. The new wrapper callers (`wrapRegisteredTool("X", ...)`) ARE structurally identical across files but are short enough (3-4 lines each) that they fall below the detection threshold. The previous GC-2026-089 inline wrappers were longer (~25 lines each) and DID register as duplicates — but they were all in the same source file group, so the count was spread differently.

The **structural goal** (eliminate the 8-file copy-paste pattern) was achieved: -169 net lines, single source of truth in the helper module. The **measurement goal** (aft_inspect count drop) was not, but the metric doesn't capture the actual concern — boilerplate in separate files is what made drift inevitable.

A future improvement: extract the registered-tool-shape test mock helpers (e.g., `makeMockPi()`, `setFakeRegistry()`) into a shared module — that would also reduce duplication.
