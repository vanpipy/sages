# GC-2026-099 — Postmortem

## What happened

Four pre-existing drift surfaces closed in one GC. Each was small
individually; together they close the typecheck / verify gap that
left a contract change in one package silently breaking the other.

| # | File(s) | Category | Pre-existing since |
|---|---|---|---|
| 1 | `pi-orchestrator/scripts/verify-catalog.ts` + `verify-gcdb.ts` | regex too narrow | introduced 2026-09-22 by GC-2026-051 T5.2; follow-up flagged by `GC-2026-institutional-coverage` 2026-10-02 |
| 2 | `pi-orchestrator/src/ui/phase-widget.ts` | duplicate type definition | phase-widget added 2026-10-05 by GC-2026-phase-widget |
| 3 | `pi-orchestrator/tsconfig.json` | missing path alias for `@sages/pi-tasks` | orchestrator declared the dep in `package.json` (`file:../pi-tasks`) but never wired the alias |
| 4 | `pi-orchestrator/test/workflow-run.test.ts` | outside typecheck scope | added by GC-2026-path-B-swap; never included in `tsconfig.json#include` |
| 5 | new `verify-pi-tasks-tools.ts` | drift between `PI_TASKS_TOOLS` allowlist and pi-tasks `registerTool` calls | the orchestrator hand-listed 7 tool names but no verify gate caught a future rename |

## Root cause

Three coupled patterns that recur across the postmortems:

- **A. Verify gates lag behind the data they guard.** The original
  `verify-gcdb.ts` (2026-09-22) used a numeric-suffix regex
  (`GC-\d{4}-\d{3,}`). Textual-suffix GCs (`GC-2026-chat-stream-render`,
  `GC-2026-precommit-fixes`, etc.) silently slipped past it. The
  `GC-2026-institutional-coverage` postmortem explicitly filed this as
  a follow-up; nobody closed it.

- **B. Type duplication when the right import is one tsconfig
  mapping away.** `phase-widget.ts` redeclared `WorkflowStartPayload`
  with a comment explaining the deliberate independence from
  pi-tasks internals — but the cost was no contract drift protection.
  The fix (import the type) costs nothing because `pi-orchestrator`
  already declares `@sages/pi-tasks: file:../pi-tasks` as a dependency.

- **C. Test files out of typecheck scope.** `workflow-run.test.ts`
  was added at the repo root (not under `test/tools/`) so it never
  showed up in `tsconfig.json#include`. It had 55 latent type errors
  (mostly an `as Harness` cast hiding a `Promise<{...}>` vs
  `{result: Promise<...>, ...}` mismatch) that went uncaught until
  R4 moved it under `test/tools/orchestrator/`. Adding it to the
  typecheck include surfaced them all; the right fix was correcting
  the `Harness.run` signature to match the actual synchronous return
  shape (with `result: Promise<WorkflowRunOutput>`), not loosening
  the typecheck.

## Fix

Six commits (one batch), distributed:

### 1. Regex broadening (`verify-catalog.ts:290-298`, `verify-gcdb.ts:76`)

```diff
- /GC-\d{4}-\d{3,}/g
+ /GC-\d{4}-[\w-]+/g
```

Both scripts gained a doc comment pointing at the institutional-coverage
postmortem follow-up that flagged the gap. Surfaced one new orphan
postmortem (`GC-2026-failure-catalog-move` — the postmortem file exists
but was missing from `gc-index.md`); fixed by adding the entry.

### 2. WorkflowStartPayload import (`phase-widget.ts:128-141`)

```diff
- interface WorkflowStartPayload {
-   workflow_id: string;
-   goal_id: string;
-   goal: { id: string; title: string; scope: { include: string[]; exclude: string[] }; anti_goals: string[]; done_definition: string };
-   max_fix_iterations: number;
-   max_redesigns?: number;
-   worktree_path: string;
- }
+ import type { WorkflowStartPayload } from "@sages/pi-tasks/workflow-handler";
```

The 14-line redundant interface is gone. If pi-tasks adds or removes a
field on `WorkflowStartPayload`, the widget's `pi.events.on("workflow:start", ...)`
handler now fails typecheck instead of silently reading `undefined`.

### 3. tsconfig path alias (`tsconfig.json:14-19`)

```diff
"paths": {
  "@/*": ["./src/*"],
  "@sages/pi-subagents": ["../pi-subagents/src/index.ts"],
  "@sages/pi-subagents/*": ["../pi-subagents/src/*"]
+ "@sages/pi-tasks": ["../pi-tasks/src/index.ts"],
+ "@sages/pi-tasks/*": ["../pi-tasks/src/*"]
}
```

Plus `test/workflow-run.test.ts` added to `include` and `../pi-tasks`
added to `exclude` (so tsc doesn't try to typecheck pi-tasks from
within pi-orchestrator's project — it's a separate package).

### 4. Test file relocation (`test/workflow-run.test.ts` → `test/tools/orchestrator/workflow-run.test.ts`)

Updated the two relative imports to match the new depth and switched
the cross-package import from `../../pi-tasks/src/workflow-handler.js`
to the alias `@sages/pi-tasks/workflow-handler` (one of the wins of
R3's tsconfig addition).

The move surfaced 55 latent type errors that were masked by being out
of scope. Fixed by correcting the `Harness.run` interface signature
(synchronous return with `result: Promise<WorkflowRunOutput>` nested
field) and removing the `as Harness` cast that hid the mismatch.
All 15 tests still pass.

### 5. PI_TASKS_TOOLS drift gate (new `verify-pi-tasks-tools.ts`)

Self-contained verifier:
- `extractAllowlist()` parses `PI_TASKS_TOOLS: readonly string[] = [...]` from `extension.ts`
- `extractRegisteredTasksToolNames()` parses every `pi.registerTool({ name: "..." })` call from `pi-tasks/src/index.ts`
- Fails if either direction drifts

```diff
$ bun run scripts/verify-pi-tasks-tools.ts
OK: pi-tasks tool allowlist matches — 7 tool(s) allowlisted, 7 registered
```

Wired into `verify-all.ts` as the 7th verifier. `package.json#scripts`
gained `verify:pi-tasks-tools` for direct invocation.

### 6. gc-index.md + GC-2026-failure-catalog-move entry

The broader regex exposed that `GC-2026-failure-catalog-move` had a
postmortem file but no `gc-index.md` row. Added the row to close the
orphan before it became a CI failure under the new regex.

## Behavior change (deliberate)

Zero runtime behavior change. All six fixes are tooling / type /
verification surfaces:

- Regex broadening: same matching set + textual IDs (no GCs were
  incorrectly classified before; the opposite — orphan detection
  is stricter now).
- WorkflowStartPayload import: type-only.
- tsconfig paths: compile-time mapping.
- Test file relocation: same tests, different path, typecheck now
  catches real bugs the test had been hiding.
- New verify gate: only fires when drift happens.
- gc-index row: documentation.

## Lessons

1. **Regex gates need updating when the data shape widens.** A
   numeric-suffix regex was fine in 2026-08 when every GC id was
   `GC-2026-NNN`. By 2026-10 the GC id format had expanded to
   textual suffixes (chat-stream-render, precommit-fixes,
   subagent-time-only-limits, etc.) and the gate stopped being a
   gate — it became a partial filter. Verify gates are part of
   the API contract; they should track the data they validate.

2. **"Deliberately independent" type definitions cost drift protection
   for no gain.** The phase-widget comment claimed independence was
   intentional. The cost was real (no typecheck on contract
   changes), the benefit was imaginary (no measurable decoupling
   gain). Import the type.

3. **Tests outside `tsconfig.include` are landmines.** They can pass
   at runtime while having any number of latent type errors. Moving
   a test into scope is a one-way trip — the resulting errors must
   be fixed, not silenced. The 55-error cleanup here was almost
   entirely real type bugs the test had been hiding.

4. **Manual takeover after a Developer abort is the right pattern
   for small mechanical GCs.** The Batch A Developer agent aborted
   at turn 60 mid-investigation. Batch B was straightforward
   (regex broadening + import refactor + new verifier) so I took
   it over manually in the worktree. ~30 min end-to-end vs the
   cost of re-dispatching with a tighter scope.
