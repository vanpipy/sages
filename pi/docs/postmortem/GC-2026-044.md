# GC-2026-044 — Sub-agent runtime state namespace

> **Date:** 2026-08-11
> **Status:** Resolved
> **Severity:** minor

## What happened

The `.pi/orchestrator/` directory mixed two kinds of state:

1. **L3 workflow state** — `goal-{id}.yaml`, `dag-{id}.yaml`,
   `audit-state-{dag_id}.yaml`, `audit-workflow.md`. Owned exclusively
   by the L3 orchestrator (the main session).
2. **Sub-agent runtime state** — diagnostics JSON from gate refusals,
   worktree-lease records from the `developer` subagent's managed
   worktree, scratch files from `git-expert` audits.

Both kinds landed in the same `.pi/orchestrator/` namespace. The L3
side had a documented ownership contract in
`pi/src/tools/orchestrator/namespace-ownership.ts`; the sub-agent side
did not. When a sub-agent wrote a diagnostic JSON into
`.pi/orchestrator/diagnostics-<task>.json`, L3's cleanup pass
(`audit-state` regen) silently overwrote it. When L3 wrote a new
`audit-workflow.md`, a sibling `developer` task's lease record got
clobbered.

The practical symptom: a DAG-2026-039 audit reported that 4 of the
12 sub-agent handoff records had been overwritten by L3 regen during
the post-batch cleanup phase. The audit had to re-derive the missing
records from `git log` and `evidence[].commits`, which cost ~25 minutes
of the audit cycle.

## Root cause

A shared namespace made ownership ambiguous. The ownership contract
in `namespace-ownership.ts` listed what each role could write, but
the **physical path** was the same. There was no filesystem-level
separation to back the logical separation.

The peer `pi-subagents/` package had been writing into `.pi/` for
months before GC-2026-044, and the precedent was "if it's not in the
deny list, it's allowed." The deny list only covered a handful of
specific filenames, not the directory as a whole.

## Fix

GC-2026-044 split the namespace:

- `.pi/orchestrator/` — L3 workflow state only (`goal-*.yaml`,
  `dag-*.yaml`, `audit-state-*.yaml`, `audit-workflow.md`). Sub-agents
  must not write here.
- `**/.pi/diagnostics/` — sub-agent runtime diagnostics. Per-package
  location (`pi/.pi/diagnostics/`, `pi-subagents/.pi/diagnostics/`,
  etc.). L3 reads but never writes.
- `**/.pi/worktree-leases/` — sub-agent worktree-lease records.
  Per-package location. Owned by `developer` subagents.

The `namespace-ownership.ts` file was updated to reflect the three
distinct paths, and the catalog generator (`gen-catalog.ts` +
`verify-catalog.ts`) was extended to enforce that any write to
`.pi/orchestrator/` came from an L3-internal call site (compile-time
check on the call chain).

The 8th catalog mode (`namespace`) was added in
`feat(pi-subagents): wire gate-refusal diagnostic + 8th catalog mode`
to mechanically verify the namespace split — every `.pi/` write site
in the codebase must declare which sub-namespace it owns.

## Follow-ups

- Keep an eye on package-level `.pi/` paths for new ones. The current
  allow-list is exhaustive at the time of resolution, but new peer
  packages added post-GC-2026-044 should be added to the namespace
  contract before their first runtime write.
- A future GC (post-GC-2026-050) will move `.pi/orchestrator/` and
  `.pi/diagnostics/` under a single `.pi/sages/` tree to make the
  Sages-owned nature of the namespace visually obvious. Out of scope
  for GC-2026-044 because the rename would have collided with the
  existing 12 package directories and required a coordinated
  migration window.
