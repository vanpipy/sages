# GC-2026-029 — Every Sages package subtree is production code

> **Date:** 2026-07-30
> **Status:** Resolved
> **Severity:** major

## What happened

The Sages monorepo contains the L3 orchestrator package (`pi/`) plus a
growing roster of peer packages (`pi-subagents/`, `pi-codebase-memory/`,
`pi-evaluator/`, etc.) that ship their own subagent prompts, dispatch
tools, and runtime. Sages Red Line #1 in `AGENTS.md` says
"the main agent must not edit production code," but until 2026-07 the
rule was applied unevenly: `pi/` was treated as production code, while
the peer packages were informally carved out as "extension code" or
"experimental code" and edited directly in the main session.

The drift showed up in two incidents:

1. A multi-file refactor of `pi-subagents/default-agents.ts` was done
   in the main session, interleaved with a user Q&A turn. The refactor
   lost its typed-artifact audit trail and broke three sibling DAG
   tasks that were already dispatched against the prior file shape.
2. A direct edit to `pi-evaluator/src/mode-toggle.ts` shipped without
   running that package's own typecheck — the L3 gate (`pi/`) passed
   but the package-level `tsc --noEmit` failed for two days.

The carve-outs existed because peer packages were originally built
outside the Sages umbrella and bolted on later. The boundary was
historical, not architectural.

## Root cause

Red Line #1 said "every Sages package subtree (`pi/`, every `pi-*/`)
is production code — no carve-outs" but the enforcement was advisory.
The bash-guard classifier recognized `pi/` paths as production but
treated `pi-*/` paths as ambiguous; `canMainAgentWrite()` returned
different answers depending on which rule was loaded first.

There was no single source of truth for "which paths count as
production code." The list was implicit in three different files
(`pi/src/tools/file-gate.ts`, `pi/src/soft-mode.ts`, and the local
overrides in each peer package's `package.json#pi.extensions`) and
drifted between them.

## Fix

GC-2026-029 contracted the meta-allowlist to root-only and removed
the carve-outs:

- `pi/src/tools/file-gate.ts` — `META_ALLOWLIST` now contains ONLY
  `.pi/orchestrator/`, `.pi/agents/`, `.claude/`, `.codex/`, root
  `README.md`, `AGENTS.md`, `package.json`, `tsconfig*.json`,
  `.gitignore`, `.aft.jsonc`. Everything else is gated.
- `pi/src/soft-mode.ts` — `isProductionTarget()` now matches any path
  inside `pi/`, `pi-*/`, `src/`, `test/`, `lib/`, or top-level
  `*.ts` / `*.json` (other than the meta-allowlist). The function
  no longer consults per-package config.
- `pi/src/tools/bash-guard.ts` — the classifier returns
  `production_code` for any write to a `pi-*/src/` or `pi-*/test/`
  path, uniformly with `pi/src/`.
- Pre-commit hooks apply uniformly: `pi/typecheck` runs all peer
  packages' typecheck scripts, not just `pi/`.

## Follow-ups

None. The fix was a strict contraction; no follow-up work was
identified in the post-merge audit.
