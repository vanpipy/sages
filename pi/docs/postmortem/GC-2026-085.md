title: Wrap orchestrator todowrite tool returns in ToolResult shape
severity: minor

## What happened

Two `todowrite` tool wrappers (`todowrite`, `todowrite_compile`) were
returning the raw `string[]` directly from their `execute` functions,
instead of the canonical ToolResult shape `{ content: [{ type: "text", text: string }] }`.
This was the same class of bug fixed for the other 5 orchestrator
tools in GC-2026-089, but the todowrite tools were left out of that
GC's scope.

## Root cause

The todowrite tools were written before the canonical ToolResult
shape was established (in the original extension loader). They were
overlooked when the other 5 orchestrator tools were fixed in
GC-2026-089.

## Fix

Wrapped the 2 todowrite tools' return values in the canonical
ToolResult shape. Added a regression test (`todowrite-shape.test.ts`)
that asserts the shape.

## Follow-ups

- The 2 todowrite tools are now wrapped in the same `wrapRegisteredTool`
  helper that the other 5 orchestrator tools use (refactored in
  GC-2026-090).
- The 2 todowrite tools are partially shadowed by the pi-tasks
  `TaskCreate` / `TaskList` surface (see `GC-2026-081.md`).
